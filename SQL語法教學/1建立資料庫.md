# DDL-1｜建立資料庫：先開一本新帳本

> 💻 DBeaver ｜ 🎯 學完你會：建立資料庫、切換到它、安全地刪除它

## 🎬 情境

你剛到「暖光咖啡」總部報到（虛構的連鎖品牌，本章一路用它當例子）。王經理丟來一句話：

> 「門市資料都散在 Excel，你弄一個資料庫放吧。」

第一步很單純：開一本新帳本，也就是**資料庫（Database）**。一個資料庫裡可以放很多張資料表，就像一個 Excel 檔裡可以有很多工作表。

| Excel | PostgreSQL |
|---|---|
| 一個 `.xlsx` 檔 | 一個 Database |
| 一張工作表 | 一張 Table |
| 第一列的標題 | Column（欄位） |
| 每一列資料 | Row（資料列） |

## 1. 建立資料庫

本章手寫練習都放在 `cafe_db`，這個資料庫會一路用到 DML 結束。

```sql
CREATE DATABASE cafe_db;
```

或者用滑鼠：在 DBeaver 左側連線底下的 **Databases** 按右鍵 → **Create New Database**。

> [!IMPORTANT]
> **九成新手卡在這裡**：建好之後，SQL 編輯器還連在舊的資料庫上！請看編輯器上方的工具列，把資料庫切換成 `cafe_db`，之後建的表才會放進去。用 SQL 建立的話，還要在左側按 `F5` 重新整理才看得到。

## 2. 看看目前有哪些資料庫

```sql
SELECT datname AS 資料庫名稱
FROM pg_database
WHERE datistemplate = false
  AND datname = 'cafe_db';
```

**執行結果**

| 資料庫名稱 |
|---|
| cafe_db |

上面多加了 `datname = 'cafe_db'` 只查這一個。拿掉那一行，就會列出全部。

## 3. 名字的潛規則

PostgreSQL 會把沒加雙引號的名字**自動轉成小寫**。寫 `CREATE DATABASE CAFE_DB` 建出來還是 `cafe_db`。

**建議的命名方式**：全小寫、用底線連接，例如 `cafe_db`、`order_items`。

## 4. 刪除資料庫

```sql
DROP DATABASE IF EXISTS 不要的資料庫名稱;
```

`IF EXISTS` 的意思是「有才刪，沒有也不要報錯」。

> [!CAUTION]
> 這會**永久刪除**裡面所有的資料表和資料，沒有資源回收桶。另外，如果你正連在這個資料庫上，它會拒絕刪除，要先切到別的資料庫。

## ⚠️ 常見卡關

| 你看到的訊息 | 原因 | 怎麼解 |
|---|---|---|
| `database "cafe_db" already exists` | 已經建過了 | 不用再建，直接切過去用 |
| `database "xxx" is being accessed by other users` | 有連線還開著 | 關掉連到它的編輯器，或切到別的資料庫再刪 |
| 左側看不到新資料庫 | 畫面還沒更新 | 選取連線按 `F5` |
| 看得到但不能展開 | DBeaver 只顯示預設資料庫 | 連線設定 → **PostgreSQL** 分頁 → 勾選 **Show all databases** |

## ✍️ 動手練

**第 1 題**：建立一個叫 `test_db` 的資料庫，確認它出現在清單中，再把它刪掉。

<details>
<summary>看答案</summary>

```sql
CREATE DATABASE test_db;
-- 按 F5 看到它之後，確認編輯器不是連在 test_db 上，再執行：
DROP DATABASE IF EXISTS test_db;
```

</details>

**第 2 題**：`DROP DATABASE test_db;` 和 `DROP DATABASE IF EXISTS test_db;` 在資料庫不存在時，差別是什麼？先猜再試。

<details>
<summary>看答案</summary>

前者會報錯 `database "test_db" does not exist`，後者只給一個提醒，不會報錯。寫成腳本重複執行時，用 `IF EXISTS` 比較不會中斷。

</details>
