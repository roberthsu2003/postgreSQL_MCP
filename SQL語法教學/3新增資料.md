# 單元 5：新增資料 (INSERT INTO)

學會建立資料表後，接著就是將真實營運資料寫入資料庫。  
本單元以連鎖咖啡門市的**「商品資料表 (`products`)」**與**「門市資料表 (`stores`)」**為例，學習各種新增資料技巧與防呆規則！

---

## 1. 基本新增語法

```sql
INSERT INTO 表格名稱 (欄位1, 欄位2, ...)
VALUES (值1, 值2, ...);
```

### ☕ 連鎖門市實戰：新增門市資料
```sql
INSERT INTO stores (name, city, address, phone)
VALUES ('台北忠孝店', '台北市', '大安區忠孝東路四段 100 號', '02-2771-0001');
```

---

## 2. 批次新增多筆資料 (Multi-Row Insert)

在實務中，單筆單筆新增效率低落，PostgreSQL 支援**一次新增多列資料**：

```sql
INSERT INTO stores (name, city, address, phone)
VALUES 
    ('台北站前店', '台北市', '中正區忠孝西路一段 50 號', '02-2311-0002'),
    ('台中勤美店', '台中市', '西區公益路 68 號', '04-2328-0003'),
    ('高雄巨蛋店', '高雄市', '左營區博愛二路 777 號', '07-5551-0004');
```

---

## 3. 省略部分欄位（未填寫的欄位會成為 NULL 或預設值）

若某個欄位有設定預設值（`DEFAULT`）或允許空值（`NULL`），新增時可以不用列出該欄位：

```sql
-- 不填寫電話，系統會自動填入 NULL
INSERT INTO stores (name, city, address)
VALUES ('新竹巨城店', '新竹市', '東區中央路 229 號');
```

---

## 4. 主鍵重複與防呆機制

若嘗試新增已經存在的主鍵 ID，PostgreSQL 會嚴格報錯：

```sql
-- 假設已有 store_id = 1，若強行指定重複主鍵：
INSERT INTO stores (store_id, name, city) VALUES (1, '重複門市', '台北市');

-- 🛑 錯誤訊息：
-- ERROR: duplicate key value violates unique constraint "stores_pkey"
```

---

## 5. 超好用技巧：新增後立刻回傳主鍵 (RETURNING)

在後續寫 Python 桌面 App 時，新增一筆訂單通常需要**「立刻拿到剛才自動產生的 `order_id`」**來新增明細。  
使用 `RETURNING` 語法可以一氣呵成：

```sql
INSERT INTO stores (name, city, address, phone)
VALUES ('台南小西門店', '台南市', '中西區西門路一段 658 號', '06-213-0005')
RETURNING store_id, name;
```

**執行結果**：
| store_id | name |
|:---:|---|
| 5 | 台南小西門店 |
