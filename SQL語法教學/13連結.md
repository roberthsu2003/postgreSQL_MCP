## 1. 把明細接回完整報表

從最細的 `order_items` 出發，順著外來鍵往外接：

```sql
SELECT
    o.order_date AS 日期,
    s.name       AS 門市,
    e.name       AS 經手,
    p.name       AS 商品,
    i.quantity   AS 數量,
    i.quantity * i.unit_price AS 小計
FROM order_items i
JOIN orders o   ON i.order_id = o.order_id
JOIN stores s   ON o.store_id = s.store_id
JOIN staff e    ON o.staff_id = e.staff_id
JOIN products p ON i.product_id = p.product_id
WHERE o.status = '已完成'
  AND o.order_date BETWEEN '2024-03-01' AND '2024-03-31'
ORDER BY o.order_date, o.order_id, p.product_id
LIMIT 5;
```

## 2. 會員是散客怎麼辦？

`customer_id` 可能是空值。用 `JOIN` 的話，散客訂單會整筆消失。

```sql
SELECT '用 JOIN' AS 寫法, COUNT(*) AS 訂單數
FROM orders o JOIN customers c ON o.customer_id = c.customer_id
UNION ALL
SELECT '用 LEFT JOIN', COUNT(*)
FROM orders o LEFT JOIN customers c ON o.customer_id = c.customer_id;
```

**執行結果**

| 寫法 | 訂單數 |
|---|---:|
| 用 JOIN | 336 |
| 用 LEFT JOIN | 490 |

差了 154 筆，正好是散客的數量。**報表少了資料，八成是該用 LEFT JOIN 卻用了 JOIN。**

## 3. 陷阱：條件放 ON 還是 WHERE？

先開一家沒有業績的新店：

```sql
INSERT INTO stores (name, address, region)
VALUES ('台南西門店', '台南市中西區西門路一段', '南部');
```

**❌ 條件放 WHERE：新店消失了**

```sql
SELECT s.name AS 門市, COUNT(o.order_id) AS 三月訂單數
FROM stores s
LEFT JOIN orders o ON s.store_id = o.store_id
WHERE o.order_date BETWEEN '2024-03-01' AND '2024-03-31'
GROUP BY s.store_id, s.name
ORDER BY s.store_id;
```

**執行結果**

| 門市 | 三月訂單數 |
|---|---:|
| 台北信義店 | 32 |
| 台北車站店 | 37 |
| 新竹巨城店 | 32 |
| 台中逢甲店 | 30 |
| 高雄巨蛋店 | 29 |

**✅ 條件放 ON：新店留下來，顯示 0**

```sql
SELECT s.name AS 門市, COUNT(o.order_id) AS 三月訂單數
FROM stores s
LEFT JOIN orders o
       ON s.store_id = o.store_id
      AND o.order_date BETWEEN '2024-03-01' AND '2024-03-31'
GROUP BY s.store_id, s.name
ORDER BY s.store_id;
```

**執行結果**

| 門市 | 三月訂單數 |
|---|---:|
| 台北信義店 | 32 |
| 台北車站店 | 37 |
| 新竹巨城店 | 32 |
| 台中逢甲店 | 30 |
| 高雄巨蛋店 | 29 |
| 台南西門店 | 0 |

**為什麼？** 新店的訂單欄位都是 `NULL`，`WHERE` 是在 JOIN 之後才篩選，`NULL` 不符合日期條件，於是整列被丟掉。放在 `ON` 則是「配對時才看」，左表不受影響。

> [!IMPORTANT]
> **LEFT JOIN 的右表條件，要放在 `ON`。** 這是職場報表最常見的錯誤之一，因為它不會報錯，只是默默少了資料。

## 4. 從業績看員工

```sql
SELECT
    s.name AS 門市,
    e.name AS 員工,
    e.title AS 職稱,
    COUNT(DISTINCT o.order_id) AS 訂單數,
    SUM(i.quantity * i.unit_price) AS 業績
FROM staff e
JOIN stores s ON e.store_id = s.store_id
JOIN orders o ON e.staff_id = o.staff_id AND o.status = '已完成'
JOIN order_items i ON o.order_id = i.order_id
GROUP BY s.store_id, s.name, e.staff_id, e.name, e.title
ORDER BY 業績 DESC
LIMIT 5;
```

**執行結果**

| 新竹巨城店 | 吳欣宜 | 店長 | 45 | 9020 |

## ⚠️ 常見卡關

| 現象 | 原因 | 怎麼解 |
|---|---|---|
| 少了散客或新店 | 該用 `LEFT JOIN` | 改用 `LEFT JOIN` |
| `LEFT JOIN` 還是少資料 | 右表條件放在 `WHERE` | 移到 `ON` |
| 金額多了好幾倍 | JOIN 時資料列被放大 | 一列一列看，檢查 `ON` |
| 對不對不知道 | 寫完沒驗算 | 拿總額和 Excel 或另一個查詢比對 |

<details>
<summary>看答案</summary>

```sql
SELECT p.name AS 商品, COALESCE(SUM(x.quantity), 0) AS 一月銷量
FROM products p
LEFT JOIN (
    SELECT i.product_id, i.quantity
    FROM order_items i
    JOIN orders o ON i.order_id = o.order_id
    WHERE o.order_date BETWEEN '2024-01-01' AND '2024-01-31'
      AND o.status = '已完成'
) x ON p.product_id = x.product_id
GROUP BY p.product_id, p.name
ORDER BY 一月銷量, p.product_id
LIMIT 4;
```
