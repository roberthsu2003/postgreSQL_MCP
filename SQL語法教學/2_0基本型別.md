# DDL-2｜資料型別：幫每一欄選對容器

> 💻 DBeaver（資料庫：`cafe_db`）｜ 🎯 學完你會：替常見欄位挑對型別，知道金額為什麼不能用 FLOAT

## 🎬 情境

Excel 什麼都能填，所以「金額」欄常會混進 `1,200元`、`待確認`、`N/A`，加總時就出錯。

資料庫要你**事先講好每一欄放什麼**。型別就像便當盒的格子：湯不會跑進飯裡，垃圾資料也塞不進來。

## 速查表：九成情況用這幾個就夠

| 要存什麼 | 用這個型別 | 咖啡店的例子 |
|---|---|---|
| 自動編號 | `SERIAL` | 門市編號 `store_id` |
| 整數 | `INT` | 數量 `quantity`、月薪 `salary` |
| **金額、要精準的小數** | `NUMERIC(10, 2)` | 報銷金額 `3850.00` |
| 長度有上限的文字 | `VARCHAR(30)` | 門市名稱、電話 |
| 不限長度的文字 | `TEXT` | 顧客留言、用途說明 |
| 日期 | `DATE` | 銷售日 `2024-03-15` |
| 時間 | `TIME` | 點餐時間 `14:30:25` |
| 日期加時間（含時區） | `TIMESTAMPTZ` | 打卡時間 |
| 是或否 | `BOOLEAN` | 是否遲到 `true` / `false` |

> [!TIP]
> `NUMERIC(10, 2)` 的意思是「總共最多 10 位數，其中 2 位是小數」，所以最大是 `99999999.99`。

## 1. 親眼看：為什麼金額不能用 FLOAT

貼上去執行：

```sql
SELECT
    0.1::FLOAT8  + 0.2::FLOAT8  AS 浮點數算的,
    0.1::NUMERIC + 0.2::NUMERIC AS 精確數算的;
```

**執行結果**

| 浮點數算的 | 精確數算的 |
|---:|---:|
| 0.30000000000000004 | 0.3 |

差的那一點點，加總幾十萬筆後就會對不上帳。**只要跟錢有關，一律用 `NUMERIC`。**

`::` 是「轉換成某型別」的寫法，先看懂就好。

## 2. 親眼看：日期型別幫你擋錯

Excel 裡打 `2024-02-30` 只會變成一段文字，要到月底算帳才發現。資料庫當場就擋下來：

```sql
SELECT '2024-02-30'::DATE;
```

> 🛑 **資料庫回應**：`date/time field value out of range: "2024-02-30"`

2 月沒有 30 號，資料根本進不去。這就是選對型別的價值。

## 3. 電話為什麼是文字，不是數字？

```sql
SELECT
    0912345678::INT     AS 存成數字,
    '0912345678'::TEXT  AS 存成文字;
```

**執行結果**

| 存成數字 | 存成文字 |
|---:|---|
| 912345678 | 0912345678 |

開頭的 `0` 不見了！判斷準則很簡單：**會拿來加減乘除的才用數字**。電話、統編、郵遞區號都用文字。

## 4. 試著組合起來

會員儲值卡需要卡號、餘額、最後加值時間、是否啟用：

```sql
CREATE TABLE gift_cards (
    card_no        VARCHAR(16) PRIMARY KEY,  -- 卡號不用計算，所以用文字
    balance        NUMERIC(10, 2),           -- 金額用 NUMERIC
    last_top_up_at TIMESTAMPTZ,              -- 日期加時間
    is_active      BOOLEAN                   -- 是或否
);

INSERT INTO gift_cards VALUES
    ('1234567890123456', 500.50, '2024-03-01 10:30:00+08', true);

SELECT card_no, balance, is_active FROM gift_cards;
```

**執行結果**

| card_no | balance | is_active |
|---|---:|---|
| 1234567890123456 | 500.50 | true |

試完把練習表收掉：

```sql
DROP TABLE gift_cards;
```

## ⚠️ 常見卡關

| 錯誤訊息 | 意思 | 怎麼解 |
|---|---|---|
| `invalid input syntax for type integer: "1,200"` | 數字欄位填了逗號或文字 | 拿掉逗號、單位 |
| `value too long for type character varying(10)` | 文字超過長度上限 | 放寬長度，或改用 `TEXT` |
| `date/time field value out of range` | 日期不存在或格式不對 | 一律寫 `YYYY-MM-DD` |

## ✍️ 動手練

替下面每個欄位選型別，蓋住答案先想一想：

1. 員工身分證字號　2. 商品售價（有小數）　3. 請假時數（整數）　4. 請假事由（長短不一）　5. 到職日　6. 是否為正職

<details>
<summary>看答案</summary>

| 欄位 | 型別 | 理由 |
|---|---|---|
| 身分證字號 | `VARCHAR(10)` | 有英文字母，也不用計算 |
| 商品售價 | `NUMERIC(10, 2)` | 金額要精準 |
| 請假時數 | `INT` | 整數，會加總 |
| 請假事由 | `TEXT` | 長度不固定 |
| 到職日 | `DATE` | 只要日期 |
| 是否為正職 | `BOOLEAN` | 只有是或否 |

</details>
