# 進階-4｜聚合與分組：SQL 版的樞紐分析表

> 💻 DBeaver（`cafe_shop`，部分用 `expense_tracker`、`hr_attendance`）｜ 📄 練習腳本：[`10聚合函式.sql`](./10聚合函式.sql) ｜ 🎯 學完你會：SUM、COUNT、AVG、GROUP BY、HAVING

## 🎬 情境

王經理：「第一季各門市業績排名，週會要用。」

在 Excel 你會插入樞紐分析表，而 SQL 只要一句話。對照一下：

| 樞紐分析表 | SQL |
|---|---|
| 「列」區域放門市 | `GROUP BY 門市` |
| 「值」區域的加總 | `SUM(金額)` |
| 「值」區域的項目個數 | `COUNT(*)` |
| 篩選器 | `WHERE` |
| 篩選加總後的結果 | `HAVING` |

## 1. 五個基本函式

| 函式 | 意思 |
|---|---|
| `COUNT(*)` | 幾筆 |
| `SUM(x)` | 加總 |
| `AVG(x)` | 平均 |
| `MAX(x)` | 最大 |
| `MIN(x)` | 最小 |

```sql
SELECT
    COUNT(*)            AS 員工數,
    SUM(salary)         AS 月薪總額,
    ROUND(AVG(salary))  AS 平均月薪,
    MAX(salary)         AS 最高月薪,
    MIN(salary)         AS 最低月薪
FROM staff;
```

**執行結果**

| 員工數 | 月薪總額 | 平均月薪 | 最高月薪 | 最低月薪 |
|---:|---:|---:|---:|---:|
| 12 | 499000 | 41583 | 55000 | 26000 |

### COUNT(*) 和 COUNT(欄位) 不一樣

```sql
SELECT
    COUNT(*)                    AS 全部訂單,
    COUNT(customer_id)          AS 有會員的訂單,
    COUNT(DISTINCT customer_id) AS 來消費過的會員人數
FROM orders;
```

**執行結果**

| 全部訂單 | 有會員的訂單 | 來消費過的會員人數 |
|---:|---:|---:|
| 490 | 336 | 50 |

| 寫法 | 算什麼 |
|---|---|
| `COUNT(*)` | 所有列 |
| `COUNT(欄位)` | 該欄不是空值的列 |
| `COUNT(DISTINCT 欄位)` | 不重複的值有幾種 |

## 2. GROUP BY：分組計算

**「各職稱有幾個人？平均月薪多少？」**

```sql
SELECT title AS 職稱, COUNT(*) AS 人數, ROUND(AVG(salary)) AS 平均月薪
FROM staff
GROUP BY title
ORDER BY 平均月薪 DESC;
```

**執行結果**

| 職稱 | 人數 | 平均月薪 |
|---|---:|---:|
| 店長 | 5 | 52200 |
| 正職咖啡師 | 5 | 37200 |
| 工讀生 | 2 | 26000 |

> [!IMPORTANT]
> **GROUP BY 鐵律**：`SELECT` 裡的欄位，要嘛放進 `GROUP BY`，要嘛包在聚合函式裡。

```sql
SELECT title, name, COUNT(*)
FROM staff
GROUP BY title;
```

> 🛑 **資料庫回應**：`column "staff.name" must appear in the GROUP BY clause or be used in an aggregate function`

每組有好幾個人，資料庫不知道 `name` 要顯示誰，所以報錯。

## 3. 回答王經理：各門市業績排名

**只算已完成的訂單**，退款不算業績：

```sql
SELECT
    s.name AS 門市,
    COUNT(DISTINCT o.order_id) AS 訂單數,
    SUM(i.quantity * i.unit_price) AS 營業額
FROM orders o
JOIN stores s ON o.store_id = s.store_id
JOIN order_items i ON o.order_id = i.order_id
WHERE o.status = '已完成'
GROUP BY s.name
ORDER BY 營業額 DESC;
```

**執行結果**

| 門市 | 訂單數 | 營業額 |
|---|---:|---:|
| 台中逢甲店 | 91 | 18795 |
| 高雄巨蛋店 | 79 | 16440 |
| 台北信義店 | 82 | 16170 |
| 新竹巨城店 | 77 | 15365 |
| 台北車站店 | 83 | 14215 |

為什麼用 `COUNT(DISTINCT o.order_id)`？因為 JOIN 明細後，一張訂單會變成好幾列，直接 `COUNT(*)` 算的是明細筆數。

## 4. 跨月分析：再也不用開三個 Excel

```sql
SELECT
    TO_CHAR(o.order_date, 'YYYY-MM') AS 月份,
    SUM(i.quantity * i.unit_price)   AS 營業額
FROM orders o
JOIN order_items i ON o.order_id = i.order_id
WHERE o.status = '已完成'
GROUP BY TO_CHAR(o.order_date, 'YYYY-MM')
ORDER BY 月份;
```

**執行結果**

| 月份 | 營業額 |
|---|---:|
| 2024-01 | 21720 |
| 2024-02 | 34140 |
| 2024-03 | 25125 |

2 月業績最高，正好是過年檔期。`TO_CHAR` 把日期轉成指定格式的文字。

## 5. HAVING：篩選分組後的結果

**「賣超過 60 份的商品有哪些？」**

```sql
SELECT p.name AS 商品, SUM(i.quantity) AS 銷量
FROM order_items i
JOIN products p ON i.product_id = p.product_id
JOIN orders o ON i.order_id = o.order_id
WHERE o.status = '已完成'
GROUP BY p.name
HAVING SUM(i.quantity) > 60
ORDER BY 銷量 DESC;
```

**執行結果**

| 商品 | 銷量 |
|---|---:|
| 翡翠檸檬綠 | 78 |
| 焦糖瑪奇朵 | 65 |
| 珍珠醇奶茶 | 61 |

**`WHERE` 和 `HAVING` 差在哪？** 看資料庫的執行順序：

```mermaid
flowchart LR
    A["FROM / JOIN<br>接好資料"] --> B["WHERE<br>先篩選每一列"] --> C["GROUP BY<br>分組"] --> D["HAVING<br>篩選每一組"] --> E["SELECT<br>挑欄位"] --> F["ORDER BY<br>排序"] --> G["LIMIT<br>取前幾筆"]
```

| | `WHERE` | `HAVING` |
|---|---|---|
| 篩選對象 | 分組前的每一列 | 分組後的每一組 |
| 能用 `SUM()` 嗎 | ❌ | ✅ |
| 例子 | `status = '已完成'` | `SUM(quantity) > 60` |

這也說明了為什麼 `ORDER BY` 能用別名 `銷量`，`WHERE` 卻不行：`SELECT` 在 `WHERE` 之後才執行。

## 6. 找忠實顧客：三個月都來消費

```sql
SELECT
    c.name AS 會員,
    COUNT(DISTINCT TO_CHAR(o.order_date, 'YYYY-MM')) AS 消費月份數,
    SUM(i.quantity * i.unit_price) AS 累計消費
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
JOIN order_items i ON o.order_id = i.order_id
WHERE o.status = '已完成'
GROUP BY c.customer_id, c.name
HAVING COUNT(DISTINCT TO_CHAR(o.order_date, 'YYYY-MM')) = 3
ORDER BY 累計消費 DESC
LIMIT 5;
```

**執行結果**

| 會員 | 消費月份數 | 累計消費 |
|---|---:|---:|
| 謝哲瑋 | 3 | 2530 |
| 林佩珊 | 3 | 2335 |
| 吳柏翰 | 3 | 1635 |
| 張美玲 | 3 | 1570 |
| 楊雅婷 | 3 | 1545 |

分組時加上 `c.customer_id`，同名的不同會員才不會被併在一起。

## 7. 換個部門也一樣

**會計（`expense_tracker`）：各部門已撥款金額**

```sql
SELECT
    d.name AS 部門,
    COUNT(*) AS 報銷筆數,
    SUM(x.amount) AS 已撥款總額
FROM expense_claims x
JOIN expense_employees e   ON x.emp_id = e.emp_id
JOIN expense_departments d ON e.dept_id = d.dept_id
WHERE x.status = '已撥款'
GROUP BY d.name
ORDER BY 已撥款總額 DESC;
```

**執行結果**

| 部門 | 報銷筆數 | 已撥款總額 |
|---|---:|---:|
| 行銷部 | 2 | 8780.00 |
| 技術部 | 2 | 8350.00 |
| 業務部 | 3 | 3430.00 |
| 人事部 | 1 | 1200.00 |

**人資（`hr_attendance`）：出勤、加班與遲到次數**

```sql
SELECT
    e.name AS 員工,
    COUNT(*) AS 出勤天數,
    SUM(a.overtime_hours) AS 總加班時數,
    COUNT(*) FILTER (WHERE a.is_late) AS 遲到次數
FROM hr_attendance_records a
JOIN hr_employees e ON a.emp_id = e.emp_id
GROUP BY e.emp_id, e.name
ORDER BY 總加班時數 DESC;
```

**執行結果**

| 員工 | 出勤天數 | 總加班時數 | 遲到次數 |
|---|---:|---:|---:|
| 林志明 | 1 | 2.0 | 1 |
| 陳小華 | 2 | 1.5 | 0 |
| 張大同 | 1 | 0.0 | 0 |
| 黃雅婷 | 1 | 0.0 | 0 |

`COUNT(*) FILTER (WHERE 條件)` 只計算符合條件的列。

## ⚠️ 常見卡關

| 錯誤訊息或現象 | 原因 | 怎麼解 |
|---|---|---|
| `must appear in the GROUP BY clause` | 欄位沒分組也沒聚合 | 加進 `GROUP BY` 或用聚合函式 |
| `aggregate functions are not allowed in WHERE` | 把 `SUM` 放進 `WHERE` | 改用 `HAVING` |
| 訂單數變很大 | JOIN 明細後每張訂單變多列 | 用 `COUNT(DISTINCT order_id)` |
| 業績比 Excel 多 | 把退款也算進去了 | 加 `WHERE status = '已完成'` |

**第 3 題**：哪個分類賺最多？列出各分類已完成訂單的營業額和毛利（`(售價 - 成本) × 數量`，售價用成交單價）。

<details>
<summary>看答案</summary>

```sql
SELECT
    c.name AS 分類,
    SUM(i.quantity * i.unit_price) AS 營業額,
    SUM(i.quantity * (i.unit_price - p.cost)) AS 毛利
FROM order_items i
JOIN orders o ON i.order_id = o.order_id
JOIN products p ON i.product_id = p.product_id
JOIN categories c ON p.category_id = c.category_id
WHERE o.status = '已完成'
GROUP BY c.name
ORDER BY 毛利 DESC;
```

|---|---:|---:|
| 義式咖啡 | 30650 | 19510 |
| 特調茶飲 | 18265 | 12937 |
