# 進階-8｜子查詢：查詢裡面再查詢

> 💻 DBeaver（`cafe_shop`，部分用 `expense_tracker`、`assets_inventory`）｜ 📄 練習腳本：[`14子查詢.sql`](./14子查詢.sql) ｜ 🎯 學完你會：單值、多值、FROM 子查詢、EXISTS，並避開 `NOT IN` 的大坑

## 🎬 情境

王經理：「薪水最高的是誰？」

你會想先查最高薪是多少，再查誰領這個數字。**把第一步包進括號，當成第二步的條件**，這就是子查詢：

```mermaid
flowchart LR
    A["內層先算：<br>最高薪是 55000"] --> B["外層再查：<br>月薪 = 55000 的人"] --> C["黃雅婷"]
```

## 1. 回傳單一值：當成條件比較

```sql
SELECT name, salary
FROM staff
WHERE salary = (SELECT MAX(salary) FROM staff);
```

**執行結果**

| name | salary |
|---|---:|
| 黃雅婷 | 55000 |

**高於平均薪資的員工：**

```sql
SELECT name, title, salary
FROM staff
WHERE salary > (SELECT AVG(salary) FROM staff)
ORDER BY salary DESC;
```

**執行結果**

| name | title | salary |
|---|---|---:|
| 黃雅婷 | 店長 | 55000 |
| 郭俊宏 | 店長 | 53000 |
| 張志明 | 店長 | 52000 |
| 許淑芬 | 店長 | 51000 |
| 吳欣宜 | 店長 | 50000 |

## 2. 回傳多筆：配 IN

**北部門市有哪些員工？**

```sql
SELECT name, title
FROM staff
WHERE store_id IN (SELECT store_id FROM stores WHERE region = '北部')
ORDER BY store_id, staff_id
LIMIT 4;
```

**執行結果**

| name | title |
|---|---|
| 張志明 | 店長 |
| 陳美玲 | 正職咖啡師 |
| 林家豪 | 工讀生 |
| 黃雅婷 | 店長 |

> [!NOTE]
> 內層回傳多筆時要用 `IN`，用 `=` 會報錯：`more than one row returned by a subquery used as an expression`。

## 3. 放在 FROM：先算一張暫時的表

**「高於平均金額的訂單有幾張？」** 要先算出每張訂單的金額，才能求平均。

```sql
SELECT COUNT(*) AS 高於平均的訂單數, ROUND(AVG(總額)) AS 這些訂單的平均
FROM (
    SELECT order_id, SUM(quantity * unit_price) AS 總額
    FROM order_items
    GROUP BY order_id
) AS 訂單金額
WHERE 總額 > (
    SELECT AVG(總額)
    FROM (
        SELECT SUM(quantity * unit_price) AS 總額
        FROM order_items
        GROUP BY order_id
    ) AS 平均用
);
```

**執行結果**

| 高於平均的訂單數 | 這些訂單的平均 |
|---:|---:|
| 199 | 323 |

括號一層一層很難讀？用 **`WITH`（CTE）** 先取名字再使用，就像 Excel 先做一張輔助工作表：

```sql
WITH 訂單金額 AS (
    SELECT order_id, SUM(quantity * unit_price) AS 總額
    FROM order_items
    GROUP BY order_id
)
SELECT COUNT(*) AS 高於平均的訂單數, ROUND(AVG(總額)) AS 這些訂單的平均
FROM 訂單金額
WHERE 總額 > (SELECT AVG(總額) FROM 訂單金額);
```

**執行結果**

| 高於平均的訂單數 | 這些訂單的平均 |
|---:|---:|
| 199 | 323 |

結果相同，但好讀多了。**實務上首選 `WITH`。**

## 4. 每個分類最貴的商品：多欄位比對

```sql
SELECT c.name AS 分類, p.name AS 商品, p.price AS 售價
FROM products p
JOIN categories c ON p.category_id = c.category_id
WHERE (p.category_id, p.price) IN (
    SELECT category_id, MAX(price)
    FROM products
    GROUP BY category_id
)
ORDER BY p.price DESC;
```

**執行結果**

| 分類 | 商品 | 售價 |
|---|---|---:|
| 義式咖啡 | 冰滴咖啡 | 150 |
| 現烤點心 | 草莓生乳千層 | 140 |
| 輕食三明治 | 經典牛肉起司堡 | 120 |
| 特調茶飲 | 靜岡抹茶歐蕾 | 110 |

## 5. EXISTS：只問「有沒有」

列出有在 2 月 14 日賣出東西的員工：

```sql
SELECT e.name
FROM staff e
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.staff_id = e.staff_id
      AND o.order_date = '2024-02-14'
)
ORDER BY e.staff_id;
```

**執行結果**

| name |
|---|
| 許淑芬 |
| 鄭建誠 |
| 郭俊宏 |

內層用了外層的 `e.staff_id`，每位員工都會跑一次，這叫**關聯子查詢**。

## 6. 大坑：NOT IN 遇到 NULL

先新增一位從沒消費的會員：

```sql
INSERT INTO customers (name, phone, gender, joined_on)
VALUES ('新來的', '0900-000-001', '女', '2024-04-01');
```

**❌ 用 NOT IN 找沒消費的會員：**

```sql
SELECT name
FROM customers
WHERE customer_id NOT IN (SELECT customer_id FROM orders);
```

**執行結果**

（查無資料，0 筆）

查不到！不是沒有這個人，而是 `orders.customer_id` 裡有散客的 `NULL`。只要清單裡有一個 `NULL`，`NOT IN` 就永遠得不到「是」。

**✅ 用 NOT EXISTS：**

```sql
SELECT c.name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id
);
```

**執行結果**

| name |
|---|
| 新來的 |

> [!CAUTION]
> **這個錯誤不會報錯，只會給你空結果，你還以為「全部會員都消費過」。** 寫「不在清單中」的查詢，一律優先用 `NOT EXISTS`。

## 7. 其他部門也用得上

**會計（`expense_tracker`）：高於平均金額的報銷**

```sql
SELECT c.name AS 類別, x.claim_date AS 日期, x.amount AS 金額, x.description AS 說明
FROM expense_claims x
JOIN expense_categories c ON x.category_id = c.category_id
WHERE x.amount > (SELECT AVG(amount) FROM expense_claims)
ORDER BY x.amount DESC
LIMIT 3;
```

**執行結果**

| 類別 | 日期 | 金額 | 說明 |
|---|---|---:|---|
| 廣告推廣 | 2024-03-05 | 8500.00 | Meta臉書春季促銷廣告費 |
| 軟體授權 | 2024-03-12 | 4500.00 | JetBrains IDE 開發工具年費 |
| 雲端服務 | 2024-03-03 | 3850.00 | AWS雲端伺服器月租扣款 |

**總務（`assets_inventory`）：庫存低於安全存量的品項**

```sql
SELECT name AS 品項, current_stock AS 庫存, safety_stock AS 安全存量
FROM assets
WHERE asset_id IN (
    SELECT asset_id FROM assets WHERE current_stock < safety_stock
)
ORDER BY name;
```

**執行結果**

| 品項 | 庫存 | 安全存量 |
|---|---:|---:|
| Double A A4 70g 影印紙(箱) | 3 | 5 |
| HP LaserJet 原廠黑色碳粉匣 | 1 | 2 |
| MacBook Pro 14吋 M3 | 0 | 1 |
| 無線便攜雷射投影機 | 0 | 1 |

這一題其實不用子查詢，直接寫 `WHERE current_stock < safety_stock` 就好。**能簡單就簡單。**

## ⚠️ 常見卡關

| 錯誤訊息或現象 | 原因 | 怎麼解 |
|---|---|---|
| `more than one row returned by a subquery` | 用 `=` 接多筆結果 | 改用 `IN` |
| `subquery in FROM must have an alias` | 舊版 PostgreSQL 要求子查詢要有名字 | 在括號後加 `AS 名字` |
| `NOT IN` 查無資料 | 子查詢裡有 `NULL` | 改用 `NOT EXISTS` |
| 括號太多看不懂 | 巢狀太深 | 改寫成 `WITH` |

**第 3 題**：用 `WITH` 算出每家門市的營業額，再列出高於平均的門市。

<details>
<summary>看答案</summary>

```sql
WITH 門市業績 AS (
    SELECT s.name, SUM(i.quantity * i.unit_price) AS 營業額
    FROM orders o
    JOIN stores s ON o.store_id = s.store_id
    JOIN order_items i ON o.order_id = i.order_id
    WHERE o.status = '已完成'
    GROUP BY s.name
)
SELECT name AS 門市, 營業額
FROM 門市業績
WHERE 營業額 > (SELECT AVG(營業額) FROM 門市業績)
ORDER BY 營業額 DESC;
```

**執行結果**

| 門市 | 營業額 |
|---|---:|
| 台中逢甲店 | 18795 |
| 高雄巨蛋店 | 16440 |

</details>

**第 4 題（總務）**：目前逾期未還的設備，以及逾期幾天。

<details>
<summary>看答案</summary>

```sql
SELECT
    a.name AS 設備,
    l.borrower_name AS 借用人,
    l.expected_return_date AS 應還日,
    CURRENT_DATE - l.expected_return_date AS 逾期天數
FROM asset_borrow_logs l
JOIN assets a ON l.asset_id = a.asset_id
WHERE l.actual_return_date IS NULL
  AND l.expected_return_date < CURRENT_DATE
ORDER BY 逾期天數 DESC;
```

`CURRENT_DATE` 是今天的日期，所以逾期天數每天都會變。

</details>
