# 產品需求文件 (PRD)：電商訂單履約與客戶 CRM 系統

* **專案代號**：`Shop-OMS-CRM`
* **開發模式**：規格驅動開發 (SDD, Spec-Driven Development)
* **資料庫環境**：PostgreSQL / Supabase ([`shop.sql`](../../範例資料庫/中文範例資料庫/shop.sql) 結構)
* **前端框架**：Streamlit (互動式 Web 應用)
* **對應範例資料庫**：👉 [`範例資料庫/中文範例資料庫/shop.sql`](../../範例資料庫/中文範例資料庫/shop.sql)

---

## 1. 專案背景與痛點

傳統中小型電商習慣將客戶訂單記錄在 Excel 檔案中，隨著訂單量擴大，衍生出許多管理災難：
1. **客戶資料重複且容易矛盾**：同一個客人購買多次，修改電話時容易漏改。
2. **缺乏即時訂單履約看板**：客服與倉管無法快速篩選「待出貨」、「已出貨」或「已取消」訂單。
3. **無法精準識別 VIP 與即將流失客**：缺乏系統化計算客戶回購頻率與累積消費金額。

本專案旨在將已正規化儲存於 PostgreSQL 中的電商資料（`shop.sql`），開發為一個**整合訂單流水線履約與客戶 CRM 分群的現代化應用**。

---

## 2. 資料庫結構 (由 MCP 讀取驗證)

資料庫已預先透過 [`shop.sql`](../../範例資料庫/中文範例資料庫/shop.sql) 建立完成，包含 6 張標準關聯表：
1. **`categories`**：商品分類（3C配件、戶外休閒、生活居家等）。
2. **`products`**：商品編號、分類ID、品名、單價、成本、庫存數量、規格。
3. **`customers`**：會員姓名、性別、電話、Email、城市、加入日期。
4. **`orders`**：訂單主檔（訂單編號、會員ID、訂單日期、付款方式、訂單狀態、送貨地址）。
5. **`order_items`**：訂單明細（訂單ID、商品ID、數量、成交單價）。
6. **`staff`**：負責客服或出貨之員工資料。

## 3. 前端介面與功能需求 (UI Requirements)

使用 **Streamlit** 開發雙模組系統：

### 3.1 模組一：訂單履約流水線 (Order Fulfillment)
- **狀態篩選器**：可切換查看「全部」、「已完成」、「處理中」、「已出貨」、「已取消」。
- **搜尋欄**：支援依「訂單編號」或「會員姓名」快速搜尋。
- **訂單明細展開視圖**：點擊任一筆訂單，即時以 SQL JOIN 展開該訂單包含的所有商品、單價、數量與小計。
- **營運 KPI 指標卡**：
  - 今日/總訂單總額
  - 平均客單價 (AOV)
  - 待出貨訂單數量

### 3.2 模組二：客戶 CRM 與 RFM 價值分群
- **RFM 模型分析表**：
  - **R (Recency)**：距離最近一次消費的天數
  - **F (Frequency)**：累計下單次數 (`COUNT(order_id)`)
  - **M (Monetary)**：累計消費總額 (`SUM(小計)`)
- **客群自動標籤**：
  - 🥇 **核心 VIP 客戶**：消費總額 TOP 10% 且下單次數 >= 2
  - 💤 **沉睡即將流失客**：超過 90 天未下單的老客戶
- **交叉銷售熱門組合 (Cross-Selling)**：利用自我連結（Self JOIN）找出經常被同一位客人一起購買的商品組合。
