## S1｜查一張訂單

```sql
SELECT p.name AS 商品,
       oi.unit_price AS 成交單價,
       oi.quantity AS 數量,
       oi.unit_price * oi.quantity AS 小計
FROM order_items oi
JOIN products p ON oi.product_id = p.product_id
WHERE oi.order_id = 1001
ORDER BY p.product_id;
```

**執行結果**

| 商品 | 成交單價 | 數量 | 小計 |
|---|---:|---:|---:|
| 保溫鋼杯 | 450 | 2 | 900 |
| 快充行動電源 | 890 | 1 | 890 |

訂單總額：

```sql
SELECT SUM(unit_price * quantity) AS 訂單總額
FROM order_items
WHERE order_id = 1001;
```

**執行結果**：`1790`

## S2｜會員買過什麼

從會員一路接到商品，要經過四張表：

```sql
SELECT o.order_date AS 日期,
       o.order_id AS 訂單,
       p.name AS 商品,
       oi.quantity AS 數量,
       oi.unit_price AS 成交單價
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p ON oi.product_id = p.product_id
WHERE c.name = '林志明'
ORDER BY o.order_date, p.product_id;
```

**執行結果**

| 日期 | 訂單 | 商品 | 數量 | 成交單價 |
|---|---:|---|---:|---:|
| 2024-03-02 | 1002 | 人體工學滑鼠墊 | 1 | 320 |
| 2024-03-12 | 1006 | 人體工學滑鼠墊 | 2 | 320 |
| 2024-03-12 | 1006 | 無線藍牙耳機 | 1 | 1290 |
| 2024-03-28 | 1010 | 無線藍牙耳機 | 1 | 1190 |

同一副耳機，林志明兩次買的價格不同，這就是成交單價要存在明細的原因。

## S4｜沒賣出的商品、沒下單的會員

```sql
SELECT p.name AS 商品, p.price AS 售價
FROM products p
LEFT JOIN order_items oi ON p.product_id = oi.product_id
WHERE oi.product_id IS NULL;
```

**執行結果**：`輕量登山背包 | 1580`

```sql
SELECT c.name AS 會員, c.email AS 信箱
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;
```

**執行結果**：`張大同 | datong@example.com`

原本 Excel 最後那兩列的問題，現在都有地方放了。

## S3｜調價不影響舊訂單

先看看，如果用**目前售價**算訂單 1001，會發生什麼事：

```sql
SELECT SUM(p.price * oi.quantity) AS 錯誤算法
FROM order_items oi
JOIN products p ON oi.product_id = p.product_id
WHERE oi.order_id = 1001;
```

**執行結果**：`1870`。客人明明付了 1790，多算了 80 元，因為保溫鋼杯已經漲到 490。

現在調漲快充行動電源：

```sql
BEGIN;

UPDATE products
SET price = 950
WHERE name = '快充行動電源'
RETURNING name, price;

COMMIT;
```

**再算一次兩種結果**：

```sql
SELECT SUM(unit_price * quantity) AS 正確算法
FROM order_items
WHERE order_id = 1001;

SELECT SUM(p.price * oi.quantity) AS 錯誤算法
FROM order_items oi
JOIN products p ON oi.product_id = p.product_id
WHERE oi.order_id = 1001;
```

| 算法 | 調價前 | 調價後 |
|---|---:|---:|
| 正確算法：成交單價 | 1790 | **1790** |
| 錯誤算法：目前售價 | 1870 | 1930 |

## S5｜建立一張完整的訂單

張大同第一次下單，買 1 個登山背包和 2 個行動電源。訂單和明細要**一起成功**，所以用交易包起來。

成交單價不用手動輸入，用 `INSERT ... SELECT` 直接從商品表帶入目前售價：

```sql
BEGIN;

INSERT INTO orders (order_id, customer_id, order_date, payment_method)
SELECT 1011, customer_id, '2024-03-30', '信用卡'
FROM customers
WHERE email = 'datong@example.com'
RETURNING order_id, customer_id, status;

INSERT INTO order_items (order_id, product_id, quantity, unit_price)
SELECT 1011, product_id, 1, price
FROM products
WHERE name = '輕量登山背包'
RETURNING order_id, product_id, quantity, unit_price;

INSERT INTO order_items (order_id, product_id, quantity, unit_price)
SELECT 1011, product_id, 2, price
FROM products
WHERE name = '快充行動電源'
RETURNING order_id, product_id, quantity, unit_price;

COMMIT;
```

**執行結果**：訂單 1011 狀態是處理中；兩筆明細的成交單價是 1580 和剛調整的 950。

```sql
SELECT SUM(unit_price * quantity) AS 訂單總額
FROM order_items
WHERE order_id = 1011;
```

**執行結果**：`3480`

這張訂單其實建錯了，要整張刪除：

```sql
BEGIN;

DELETE FROM orders WHERE order_id = 1011 RETURNING order_id;

SELECT COUNT(*) AS 剩餘明細 FROM order_items WHERE order_id = 1011;
SELECT name AS 會員仍在 FROM customers WHERE email = 'datong@example.com';

COMMIT;
```

**執行結果**：`剩餘明細` 是 **0**，`會員仍在` 是 **張大同**。明細被 `ON DELETE CASCADE` 一起刪除，會員資料不受影響，Excel 的刪除問題解決了。

## ⚠️ 常見卡關

| 狀況 | 原因 | 怎麼解 |
|---|---|---|
| 訂單總額和 Excel 不同 | 用了 `products.price` | 舊訂單要用 `oi.unit_price` |
| `column reference "name" is ambiguous` | 多張表都有 `name` | 寫清楚 `c.name`、`p.name` |
| 第二次建立訂單出現 `orders_pkey` | 訂單編號重複 | 換一個訂單編號，或先刪除舊訂單 |
| `INSERT ... SELECT` 後筆數是 0 | `WHERE` 的名稱或信箱打錯 | 先單獨執行 `SELECT` 確認 |
| `current transaction is aborted` | 交易中有一句失敗 | 先執行 `ROLLBACK;` |
