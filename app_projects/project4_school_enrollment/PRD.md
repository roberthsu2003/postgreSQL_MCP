# 產品需求文件 (PRD)：校園智慧選課與學分審查系統

* **專案代號**：`School-Course-Enrollment`
* **開發模式**：規格驅動開發 (SDD, Spec-Driven Development)
* **資料庫環境**：PostgreSQL / Supabase ([`school.sql`](../../範例資料庫/中文範例資料庫/school.sql) 結構)
* **前端框架**：Streamlit (互動式 Web 應用)
* **對應範例資料庫**：👉 [`範例資料庫/中文範例資料庫/school.sql`](../../範例資料庫/中文範例資料庫/school.sql)

---

## 1. 專案背景與痛點

大專院校每學期選課期間，教務處與學生面臨嚴峻挑戰：
1. **衝堂與修課衝突**：學生常因無法即時確認時段，選到時間衝突的課程。
2. **名額超收與名額爭議**：缺乏原子性（Atomicity）資料庫交易保護，容易造成熱門課程超收。
3. **學分畢業進度不清**：學生無法即時知道自己「必修、選修、通識」各累積了多少學分，常在畢業前夕才發現學分不足。

本專案將基於已正規化建置的 `school.sql`，打造一個**兼具選課防衝堂檢核、即時剩餘名額查看與個人畢業學分進度審查的校園 Web 應用**。

---

## 2. 資料庫結構 (由 MCP 讀取驗證)

資料庫已預先透過 [`school.sql`](../../範例資料庫/中文範例資料庫/school.sql) 建立完成，包含 5 張標準關聯表：
1. **`departments`**：學系資料（系代碼、系所名稱、辦公室位置）。
2. **`teachers`**：專任與兼任教師（教師編號、姓名、職稱、所屬學系）。
3. **`students`**：學生基本資料（學號、姓名、所屬學系、入學年度、聯絡電話）。
4. **`courses`**：課程主檔（課程編號、課程名稱、學分數、授課教師、開課學系、上課時間、名額上限）。
5. **`enrollments`**：學生選課與成績紀錄（學號、課程編號、學期、成績、選課狀態）。

## 3. 前端介面與功能需求 (UI Requirements)

使用 **Streamlit** 開發三大功能分頁：

### 3.1 學生個人選課中心 (Enrollment Dashboard)
- **學生身份切換**：下拉選單模擬切換不同學號之學生。
- **本學期已選課表 (Timetable)**：視覺化呈現週一至週五排課時段，一秒看清空堂與已選課程。
- **課程搜尋與名額即時狀態**：
  - 依系所、學分數、課程名稱關鍵字篩選。
  - 顯示目前已選人數 vs. 名額上限（例如：`38 / 40 人 (即將額滿)`）。
- **衝堂防呆檢核**：若點擊選課時時段與已選課程重疊，即時彈出警示並禁止送出。

### 3.2 畢業學分審核進度條 (Degree Audit)
- 統計已修過且及格之總學分。
- 分類進度條：
  - 本系必修學分達成率
  - 系內選修學分達成率
  - 外系與通識學分達成率
- 未修畢之必修課程清單自動提示。

### 3.3 教師與系所營運統計 (Faculty Analytics)
- 統計各學系開課總堂數、總修課人次。
- 滿班率排行（哪些課程滿班率達 100%）。
