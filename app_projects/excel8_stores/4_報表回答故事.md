## S1｜各門市每月營業額

`GROUP BY` 就像樞紐分析表的「列」：

```sql
SELECT s.name AS 門市,
       TO_CHAR(o.order_date, 'YYYY-MM') AS 月份,
       SUM(oi.quantity * oi.unit_price) AS 營業額
FROM orders o
JOIN stores s ON o.store_id = s.store_id
JOIN order_items oi ON o.order_id = oi.order_id
WHERE o.status = '已完成'
GROUP BY s.name, TO_CHAR(o.order_date, 'YYYY-MM')
ORDER BY s.name, 月份;
```

## S2｜熱銷前 5 名

```sql
SELECT p.name AS 商品,
       SUM(oi.quantity) AS 銷售數量,
       SUM(oi.quantity * oi.unit_price) AS 營業額
FROM order_items oi
JOIN orders o ON oi.order_id = o.order_id
JOIN products p ON oi.product_id = p.product_id
WHERE o.status = '已完成'
GROUP BY p.product_id, p.name
ORDER BY 銷售數量 DESC, 營業額 DESC
LIMIT 5;
```

## S3｜每個月都來的會員

`HAVING` 是分組之後才篩選。重點是**用 `customer_id` 分組**，同名的人才不會被合併：

```sql
SELECT c.name AS 會員,
       c.phone AS 電話,
       COUNT(DISTINCT TO_CHAR(o.order_date, 'YYYY-MM')) AS 消費月份數,
       SUM(oi.quantity * oi.unit_price) AS 累計消費
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
WHERE o.status = '已完成'
GROUP BY c.customer_id, c.name, c.phone
HAVING COUNT(DISTINCT TO_CHAR(o.order_date, 'YYYY-MM')) = 3
ORDER BY 累計消費 DESC;
```

**執行結果**：共 **24 位**會員，前 5 名如下：

| 會員 | 電話 | 消費月份數 | 累計消費 |
|---|---|---:|---:|
| 謝哲瑋 | 0963-728-214 | 3 | 2530 |
| 林佩珊 | 0937-416-656 | 3 | 2335 |
| 吳柏翰 | 0943-964-617 | 3 | 1635 |
| 張美玲 | 0970-286-845 | 3 | 1570 |
| 楊雅婷 | 0919-408-409 | 3 | 1545 |

名單中有兩位謝哲瑋，電話不同，是不同的人。如果改成 `GROUP BY c.name`，只會得到 **20** 位：不但少發優惠券，消費金額也會被算在一起。

## S4｜業績高於平均的店員

先用 `WITH` 算出每位店員的業績，再和平均值比較：

```sql
WITH staff_sales AS (
    SELECT st.name AS 店員,
           s.name AS 門市,
           SUM(oi.quantity * oi.unit_price) AS 業績
    FROM orders o
    JOIN staff st ON o.staff_id = st.staff_id
    JOIN stores s ON st.store_id = s.store_id
    JOIN order_items oi ON o.order_id = oi.order_id
    WHERE o.status = '已完成'
    GROUP BY st.staff_id, st.name, s.name
)
SELECT 店員, 門市, 業績
FROM staff_sales
WHERE 業績 > (SELECT AVG(業績) FROM staff_sales)
ORDER BY 業績 DESC;
```

**執行結果**：12 位店員的平均業績約為 6749，高於平均的有 6 位。

## S5｜下個月的資料來了

4 月的資料包含一位新會員和一項新商品。**以後每個月都只要做這三步**：

**第一步：清空暫存表**

```sql
TRUNCATE raw_sales;
```

**第二步：匯入 CSV**

用 DBeaver 把 [`門市銷售明細_202404.csv`](./門市銷售明細_202404.csv) 匯入 `raw_sales`，然後確認：

```sql
SELECT COUNT(*) AS 筆數, SUM(小計::INT) AS 總金額 FROM raw_sales;
```

**執行結果**：`7` 筆、`745` 元。

**第三步：執行同一份匯入腳本**

執行上一步的匯入腳本，再查筆數：

```sql
SELECT (SELECT COUNT(*) FROM products) AS 商品,
       (SELECT COUNT(*) FROM customers) AS 會員,
       (SELECT COUNT(*) FROM orders) AS 訂單,
       (SELECT COUNT(*) FROM order_items) AS 明細;
```

**執行結果**

| 商品 | 會員 | 訂單 | 明細 |
|---:|---:|---:|---:|
| 19 | 51 | 495 | 789 |

多了 1 項商品、1 位會員、5 張訂單、7 筆明細。**再執行一次匯入腳本**，然後再查一次，結果完全相同：`ON CONFLICT DO NOTHING` 跳過了已經存在的資料。

> [!NOTE]
> 重複匯入後，自動編號可能會跳號，這是正常的。商品調價不會由這份腳本更新，要用專案 5 的 `UPDATE` 處理。

## ⚠️ 常見卡關

| 狀況 | 原因 | 怎麼解 |
|---|---|---|
| `must appear in the GROUP BY clause` | 欄位沒分組也沒聚合 | 把欄位加進 `GROUP BY` |
| 忠誠會員不是 24 位 | 用了姓名分組，或忘了篩選已完成 | 用 `c.customer_id` 分組 |
| 營業額比 80985 多 | 忘了 `WHERE o.status = '已完成'` | 補上條件，退款不算營收 |
| `WHERE` 不能放 `COUNT` | 聚合條件要放 `HAVING` | 改用 `HAVING` |
| 匯入後筆數沒變 | 暫存表還是舊資料 | 先 `TRUNCATE raw_sales;` 再匯入新 CSV |
