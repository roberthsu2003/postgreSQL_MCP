# 步驟 1｜哪些欄位放 JSONB：固定的開欄位，不固定的放規格

> 💻 Excel ｜ 🎯 學完你會：判斷哪些資料適合 JSONB，哪些應該開正常欄位

> 📚 先修：[DML-6 JSONB](../../SQL語法教學/16json.md)。

## 🎬 情境

打開 [`設備規格表.xlsx`](./設備規格表.xlsx) 的「設備清單」，再看「需求」工作表：

| 編號 | 故事 | 驗收條件 |
|:---:|---|---|
| S1 | 身為資訊人員，我想要找出記憶體 16GB 以上的筆電，這樣才能安排給需要跑大型軟體的同仁 | 只列出筆電，記憶體由大到小 |
| S2 | 身為總務，我想要查看所有投影機的亮度和解析度，這樣才能依會議室大小借用 | 列出 4 台投影機，亮度由高到低 |
| S3 | 身為行政，我想要找出支援雙面列印的印表機，這樣才能節省紙張 | 只列出雙面列印是「是」的印表機 |
| S4 | 身為資訊人員，我想要登記筆電升級記憶體，這樣規格資料才會保持正確 | 只有記憶體改變，CPU 和螢幕不受影響 |
| S5 | 身為資訊人員，我想要登記新類型的設備，不用新增欄位，這樣清單才不會越加越寬 | 新增一台平板，有自己的規格，資料表結構不用修改 |

## 1. 這張表的問題

看看筆電那一列：亮度、解析度、列印速度、雙面列印、紙張全是空白。

| 類型 | 用得到的規格欄 | 空白的規格欄 |
|---|---:|---:|
| 筆電 | 3 | 5 |
| 投影機 | 2 | 6 |
| 印表機 | 3 | 5 |

如果明年多買平板，又要再加作業系統、儲存空間這些欄位，其他設備全部都是空白。

## 2. 分成固定欄位和規格

問自己：**每一台設備都有嗎？**

| Excel 標題 | 每台都有？ | 放哪裡 |
|---|:---:|---|
| 設備編號、品名、類型、購入日、單價、使用部門 | ✅ | 正常欄位 |
| CPU、記憶體、螢幕 | 只有筆電 | `specs` JSONB |
| 亮度、解析度 | 只有投影機 | `specs` JSONB |
| 列印速度、雙面列印、紙張 | 只有印表機 | `specs` JSONB |

單價和購入日每台都有，而且常用來計算或篩選，所以開正常欄位。

## 3. 決定規格的名稱

JSON 裡的名稱用英文，寫 SQL 時比較不容易出錯：

| Excel 標題 | JSON 名稱 | 內容 | 例子 |
|---|---|---|---|
| CPU | `cpu` | 文字 | `"i7-1365U"` |
| 記憶體(GB) | `ram_gb` | 數字 | `16` |
| 螢幕(吋) | `screen_inch` | 數字 | `14` |
| 亮度(流明) | `lumens` | 數字 | `3000` |
| 解析度 | `resolution` | 文字 | `"1920x1080"` |
| 列印速度(頁/分) | `ppm` | 數字 | `38` |
| 雙面列印 | `duplex` | true / false | `true` |
| 紙張 | `paper` | 文字 | `"A4"` |

一台筆電的規格會長這樣：

```json
{"cpu": "i7-1365U", "ram_gb": 16, "screen_inch": 14}
```

> [!TIP]
> 空白的欄位**不要放進 JSON**。筆電的規格裡不需要 `lumens`，這正是用 JSONB 的好處。

## ⚠️ 常見卡關

| 狀況 | 怎麼想 |
|---|---|
| 單價要不要放 JSON | 不要。每台都有，又要計算，開正常欄位 |
| 全部都放 JSON 不是更省事 | 不行，資料庫就無法幫你檢查型別和必填 |
| 雙面列印存「是」還是 true | 存 `true` / `false`，查詢時才好判斷 |
