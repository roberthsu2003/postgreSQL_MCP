# 步驟 1｜哪些欄位該獨立、哪些欄位放進 JSONB？

> 先打開 [設備規格表.xlsx](設備規格表.xlsx)，看看 `設備清單` 工作表：雖然只有 16 列，但欄位竟然拉到 **14 欄**，而且右半邊一整片都是空的！

## 這張 Excel 為什麼痛？

- 筆電需要「CPU、記憶體、螢幕」，投影機和印表機根本沒有這些東西，格子只能留白。
- 印表機的「雙面列印」在 Excel 寫成「是／否」，過兩天換同事填表可能就寫成「有／無」、「True／False」。
- 以後要多買 **平板、網路交換器、視訊攝影機**，Excel 就要一直往右邊加欄位，舊設備全部填空，整張表越長越歪！

**JSONB 的核心精神**：
- **所有設備都有**、而且會拿來做主要分類或預算統計的 → **寫成固定欄位**。
- **只有某些設備才有**、不同類型各有各的規格 → **打包進同一欄 `specs JSONB`**！

## 分類練習：14 個欄位要放哪一邊？

| 類型 | Excel 欄位 | 資料庫位置 | 理由 |
|---|---|---|---|
| **共通欄位** | 設備編號、品名、類型、購入日、單價、使用部門 | **獨立固定欄位**（`device_id`, `name`, `device_type`, `purchase_date`, `price`, `department`） | 每一台設備都一定要有，適合建主鍵、統計總金額與篩選類型 |
| **筆電規格** | CPU、記憶體(GB)、螢幕(吋) | 塞進 **`specs JSONB`**（`cpu`, `ram_gb`, `screen_inch`） | 投影機與印表機用不到 |
| **投影機規格** | 亮度(流明)、解析度 | 塞進 **`specs JSONB`**（`lumens`, `resolution`） | 筆電與印表機用不到 |
| **印表機規格** | 列印速度(頁/分)、雙面列印、紙張 | 塞進 **`specs JSONB`**（`ppm`, `duplex`, `paper`） | 其中 `duplex` 要存布林值 `true`/`false`，不再用「是／否」 |

## ✍️ 動手練（先想清楚規則，再進入步驟 2）

1. **找一找為什麼 Excel 資料類型很危險**：觀察 `設備清單` 裡的 `雙面列印` 欄和 `單價` 欄，為什麼 `雙面列印` 改存進 JSONB 時建議存成 JSON 布林值 `true` / `false`，而不是字串 `"是"` / `"否"`？
   <details>
   <summary>👀 點開看解答</summary>

   - 存成 `"是"` / `"否"` 容易出現有人打 `"有"`、`"Y"`、`"支援"` 的亂象；存成真正的 JSON 布林值 `true` / `false`（不加引號），SQL 查詢時就能用 `(specs->>'duplex')::BOOLEAN = true` 精準比對。
   </details>

2. **驗算基準數字**：在 `設備清單` 工作表用 Excel 公式算出總台數和採購總金額（單價在 E 欄 `E2:E17`），並數數看各有幾台筆電、投影機、印表機？
   <details>
   <summary>👀 點開看核對數字</summary>

   - 總台數：`=COUNTA(A2:A17)` → **16 台**（筆電 8 台、投影機 4 台、印表機 4 台）。
   - 採購總金額：`=SUM(E2:E17)` → **466,000 元**。
   </details>

3. **看懂「有問題的資料」工作表**：試著猜猜 `NB-101`（規格完全空白）和 `NB-104`（用了單引號 `{'cpu': 'i5'}`）在 PostgreSQL 會被哪兩種機制攔下來？
   <details>
   <summary>👀 點開看答案</summary>

   - `NB-101` 沒有規格：如果我們把 `specs` 設為 **`NOT NULL`**，空白就會被擋下（至少要給 `{}` 或完整 JSON）。
   - `NB-104` 用單引號 `{'cpu': 'i5'}`：標準 JSON **一律必須用雙引號 `"` 包住鍵和文字值**，所以 `JSONB` 型別在寫入當下就會立刻報錯拒絕！
   </details>
