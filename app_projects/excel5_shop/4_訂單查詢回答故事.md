### 題目 1（S1）：查詢單張訂單明細與訂單總額（1001）

- **驗收條件**：訂單 `1001` 有 2 項：`保溫鋼杯`（450 × 2 = 900）、`快充行動電源`（890 × 1 = 890），總額 **`1790`**。
- **✍️ 在 DBeaver 動手作提示**：注意金額要算 **`oi.unit_price`（當時成交單價）**，不是 `p.price`！

### 題目 5（S5）：用 Transaction ＋ `INSERT ... SELECT` 建立多品項訂單 1011 再測 `CASCADE` 刪除

- **業務問題**：
  1. 開啟 `BEGIN; ... COMMIT;` 交易：替會員 **`張大同（customer_id = 5）`** 建立訂單 **`1011`**（日期 `'2024-04-01'`、`'信用卡'`、`'處理中'`），並用 **`INSERT INTO order_items ... SELECT ... FROM products`** 自動帶入目前售價，購買 `輕量登山背包` 1 個（1580）＋ `快充行動電源` 2 個（**用 S3 剛調漲的 950！**）。查詢 `1011` 總額應為 **`3480`**。
  2. 模擬這張訂單建錯需要整張作廢：執行 `BEGIN; DELETE FROM orders WHERE order_id = 1011; ... COMMIT;`，驗證因為外來鍵設有 **`ON DELETE CASCADE`**，訂單明細會自動歸 `0` 筆，且會員 `張大同` 依然留在 `customers` 中！
- **驗收條件**：`1011` 明細總額為 `1580 + 950*2 = 3480`；刪除後 `order_items` 針對 `1011` 為 **`0` 筆**，`customers` 依然保有 `5` 位會員（含張大同）。
- **✍️ 在 DBeaver 動手作提示**：練習 `INSERT INTO order_items ... SELECT` 自動讀取 `products.price` 當 `unit_price`。

### 題目 8（E3）：會員累積有效消費額排行（排除「已取消」，含零消費會員）

- **業務問題**：做簡易 VIP 會員榜：統計全部 **5 位會員**各自的「有效訂單數（`status <> '已取消'`）」與「累積有效消費額」，沒有買過東西的張大同也要以 `0` 列出來，依消費額由高到低排列！
- **驗收條件**：`陳小華` 第一名（3 單、`4,430`）；`黃雅婷` 因 `1004` 取消而只計入 `1007`（1 單、`770`）；`張大同`（0 單、`0`）。
- **✍️ 在 DBeaver 動手作提示**：從 `customers` 做兩層 `LEFT JOIN`，並使用 `FILTER (WHERE o.status <> '已取消')` 搭配 `COALESCE(..., 0)`（注意若直接寫 `WHERE o.status <> '已取消'` 會把張大同過濾掉！）。

<details>
<summary>👀 寫完再打開：參考 SQL 與預期執行結果（5 筆）</summary>

```sql
SELECT
    c.customer_id,
    c.name AS 會員姓名,
    c.city AS 城市,
    COUNT(DISTINCT o.order_id) FILTER (WHERE o.status <> '已取消')                  AS 有效訂單數,
    COALESCE(SUM(oi.quantity * oi.unit_price) FILTER (WHERE o.status <> '已取消'), 0) AS 累積有效消費額
FROM customers c
LEFT JOIN orders o       ON c.customer_id = o.customer_id
LEFT JOIN order_items oi ON o.order_id = oi.order_id
GROUP BY c.customer_id, c.name, c.city
ORDER BY 累積有效消費額 DESC, c.customer_id;
```

- **業務問題**：營運想知道三種付款方式（排除已取消訂單）各自有多少張有效訂單、多少總營收、以及佔全部有效營收（`10,790` 元）的百分比（四捨五入到小數點後 1 位）。
- **驗收條件**：`信用卡` 4 單 `4,710`（`43.7%`）、`LINE Pay` 3 單 `3,440`（`31.9%`）、`貨到付款` 2 單 `2,640`（`24.5%`）。
- **✍️ 在 DBeaver 動手作提示**：先在 `WITH valid_orders AS (...)` 算出每張有效訂單自己的小計總額，外層再按 `payment_method` 加總並用 `SUM(SUM(訂單金額)) OVER ()` 當分母算百分比！

<details>
<summary>👀 寫完再打開：參考 SQL 與預期執行結果（3 筆）</summary>

```sql
WITH valid_orders AS (
    SELECT
        o.order_id,
        o.payment_method,
        SUM(oi.quantity * oi.unit_price) AS 訂單金額
    FROM orders o
    JOIN order_items oi ON o.order_id = oi.order_id
    WHERE o.status <> '已取消'
    GROUP BY o.order_id, o.payment_method
)
SELECT
    payment_method AS 付款方式,
    COUNT(*)       AS 訂單數,
    SUM(訂單金額)  AS 總營收,
    ROUND(100.0 * SUM(訂單金額) / SUM(SUM(訂單金額)) OVER (), 1) AS 營收佔比百分比
FROM valid_orders
GROUP BY payment_method
ORDER BY 總營收 DESC;
```

| 付款方式 | 訂單數 | 總營收 | 營收佔比百分比 |
|---|---|---|---|
| 信用卡 | 4 | 4710 | 43.7 |
| LINE Pay | 3 | 3440 | 31.9 |
| 貨到付款 | 2 | 2640 | 24.5 |

*(註：小數第 1 位四捨五入後總和為 `100.1%`，屬於顯示捨入正常現象)*

</details>

### 題目 10（E5）：進階交易沙盒 — 用 `INSERT ... SELECT` 建多品項單後再調價驗證歷史隔離

- **業務問題**：開啟 **`BEGIN; ... ROLLBACK;`** 安全沙盒演練一段完整的電商時序場景：
  1. 幫會員 `張大同（customer_id = 5）` 建立訂單 `1012`（日期 `'2024-04-02'`、`'LINE Pay'`、`'已完成'`），用 `INSERT ... SELECT ... FROM products` 一次寫入 `輕量登山背包`（qty 1，1580）與 `快充行動電源`（qty 2，950）。
  2. 接著把 `輕量登山背包` 的 `products.price` 調漲為 `1680`。
  3. 查詢確認訂單 `1012` 的 `輕量登山背包` 成交價仍然鎖在 **`1580`** 而非 `1680`，最後 **`ROLLBACK;`** 讓資料庫回到 `10` 張訂單、背包仍為 `1580`！
- **驗收條件**：沙盒內總訂單變成 `11`、背包售價 `1680` 但 `1012` 成交單價仍是 `1580`；`ROLLBACK;` 後復原回 `10` 張訂單、背包售價 **`1580`**。
- **✍️ 在 DBeaver 動手作提示**：`INSERT INTO order_items ... SELECT 1012, product_id, qty, price FROM (VALUES ...) AS cart(prod_name, qty) JOIN products ...` 是超實用的批次回填技巧！

<details>
<summary>👀 寫完再打開：參考 SQL 與沙盒前後對照結果</summary>

```sql
BEGIN;

-- 1. 建立訂單 1012 與兩筆明細（自動從 products 抓取目前售價）
INSERT INTO orders (order_id, customer_id, order_date, payment_method, status)
VALUES (1012, 5, '2024-04-02', 'LINE Pay', '已完成');

INSERT INTO order_items (order_id, product_id, quantity, unit_price)
SELECT 1012, product_id, qty, price
FROM (VALUES ('輕量登山背包', 1), ('快充行動電源', 2)) AS cart(prod_name, qty)
JOIN products p ON p.name = cart.prod_name;

-- 2. 模擬建單後隨即調漲輕量登山背包目前售價至 1680
UPDATE products SET price = 1680 WHERE name = '輕量登山背包';

-- 3. 對照 1012 明細中的成交單價（不隨目前售價異動而改變）
SELECT o.order_id, p.name, oi.unit_price AS 沙盒訂單成交單價, p.price AS 調價後目前售價
FROM order_items oi
JOIN orders o   ON oi.order_id = o.order_id
JOIN products p ON oi.product_id = p.product_id
WHERE o.order_id = 1012
ORDER BY p.product_id;

SELECT COUNT(*) AS 沙盒訂單數 FROM orders; -- 11

-- 4. 回滾復原
ROLLBACK;

SELECT COUNT(*) AS 復原後訂單數 FROM orders; -- 10
SELECT name, price AS 復原後背包售價 FROM products WHERE name = '輕量登山背包'; -- 1580
```

| 商品 | 沙盒訂單成交單價 | 沙盒調價後目前售價 | `ROLLBACK;` 後目前售價 |
|---|---|---|---|
| 快充行動電源 | 950 | 950 | 950 |
| 輕量登山背包 | **1580** | 1680 | **1580** |

</details>
