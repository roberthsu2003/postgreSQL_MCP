### 題目 1（S1）：不分大小寫與寫法的多關鍵字模糊搜尋（`ILIKE`）

- **業務問題**：客服想找出所有跟無線網路（Wi-Fi）有關的案件。因為同事在 Excel 裡同時寫過 `WiFi`、`wifi`、`WIFI` 和 `Wi-Fi`，單靠 `=` 或只寫 `%wifi%` 都會漏掉 `Wi-Fi`！請寫出一次通吃這四種寫法的 SQL。
- **驗收條件**：應精準命中 **6 筆**（`T001`, `T005`, `T009`, `T013`, `T020`, `T028`），特別確定 `T013` 的 `Wi-Fi` 有被抓到。
- **✍️ 在 DBeaver 動手作提示**：用 `ILIKE '%wifi%' OR ... ILIKE '%wi-fi%'`（`ILIKE` 在 PostgreSQL 會自動忽略大小寫）。

<details>
<summary>👀 寫完再打開：參考 SQL 與預期執行結果（6 筆）</summary>

```sql
SELECT t.ticket_id, t.created_on, t.customer_name, t.description, t.status
FROM tickets t
WHERE t.description ILIKE '%wifi%'
   OR t.description ILIKE '%wi-fi%'
ORDER BY t.ticket_id;
```

### 題目 2（S2）：統計各分類總件數與未結案件數（`GROUP BY` ＋ `FILTER`）

- **業務問題**：客服主管想看 4 個問題分類各自「總共收過幾件」、「還有幾件未結案（`status <> '已結案'`）」，依未結案件數由多到少排列。
- **驗收條件**：`軟體操作` 總共 **8** 件、未結案 **5** 件排第一；`網路連線` 8 件、未結案 3 件。
- **✍️ 在 DBeaver 動手作提示**：`COUNT(*) FILTER (WHERE t.status <> '已結案')` 可以不改 `WHERE` 就直接在同一個分組裡做條件計數！

<details>
<summary>👀 寫完再打開：參考 SQL 與預期執行結果（4 筆）</summary>

SELECT
    c.name AS 分類,
    COUNT(*) AS 總件數,
    COUNT(*) FILTER (WHERE t.status <> '已結案') AS 未結案件數
FROM tickets t
JOIN categories c ON t.category_id = c.category_id
GROUP BY c.category_id, c.name
ORDER BY 未結案件數 DESC, 總件數 DESC, c.category_id;

### 題目 3（S3）：找出高負荷處理人員（`HAVING COUNT(*) >= 3`）

- **業務問題**：主管想找出目前手頭上「未結案案件（`status <> '已結案'`）累積 **3 件（含）以上**」的處理人員，只列出超過負荷的人方便重新調配工作。
- **驗收條件**：在 S5 尚未結案 T030 之前應查出 **2 人**：`張育誠`（5 件，分機 104）與 `陳怡君`（3 件，分機 101）。
- **✍️ 在 DBeaver 動手作提示**：注意 **`WHERE`** 先過濾未結案案件，**`GROUP BY`** 分組後再用 **`HAVING COUNT(*) >= 3`** 篩人數！（不能把彙總條件寫在 `WHERE` 裡）。

<details>
<summary>👀 寫完再打開：參考 SQL 與預期執行結果（2 筆）</summary>

```sql
SELECT
    a.name      AS 處理人員,
    a.extension AS 分機,
    COUNT(*)    AS 未結案件數
FROM tickets t
JOIN agents a ON t.agent_id = a.agent_id
WHERE t.status <> '已結案'
GROUP BY a.agent_id, a.name, a.extension
HAVING COUNT(*) >= 3
ORDER BY 未結案件數 DESC, a.agent_id;
```

| 處理人員 | 分機 | 未結案件數 |
|---|---|---|
| 張育誠 | 104 | 5 |

### 題目 9（E4）：計算已結案案件的平均處理天數（`closed_on - created_on`）

- **業務問題**：在 PostgreSQL 裡，兩個 `DATE` 型別直接相減就會得到整數「天數」！請針對所有已結案案件（S5 後共 `20` 件），分別算出各問題分類的「已結案件數」、「平均處理天數（四捨五入到小數第 2 位）」與「最長天數」，並多查一次全體平均天數。
- **驗收條件**：`硬體設備` 平均 **`2.20`** 天最久，`帳號權限` **`0.67`** 天最快；全體 20 件已結案平均為 **`1.50`** 天。
- **✍️ 在 DBeaver 動手作提示**：`ROUND(AVG(t.closed_on - t.created_on), 2)`，條件記得寫 `WHERE t.status = '已結案'`。

<details>
<summary>👀 寫完再打開：參考 SQL 與預期執行結果</summary>

```sql
-- 1. 各分類結案處理天數統計
SELECT
    c.name                                    AS 分類,
    COUNT(*)                                  AS 已結案件數,
    ROUND(AVG(t.closed_on - t.created_on), 2) AS 平均處理天數,
    MAX(t.closed_on - t.created_on)           AS 最長天數
FROM tickets t
JOIN categories c ON t.category_id = c.category_id
WHERE t.status = '已結案'
GROUP BY c.category_id, c.name
ORDER BY 平均處理天數 DESC;

-- 2. 全體已結案平均處理天數
SELECT
    COUNT(*)                              AS 全部已結案件數,
    ROUND(AVG(closed_on - created_on), 2) AS 全體平均處理天數
FROM tickets
WHERE status = '已結案';
```

| 分類 | 已結案件數 | 平均處理天數 | 最長天數 |
|---|---|---|---|
| 硬體設備 | 5 | 2.20 | 4 |
| 軟體操作 | 4 | 2.00 | 4 |
| 網路連線 | 5 | 1.40 | 3 |
| 帳號權限 | 6 | 0.67 | 2 |

- 全體 20 件已結案：平均處理天數 **`1.50`** 天。

</details>

### 題目 10（E5）：進階交易沙盒 — 誤填過早結案日觸發 `CHECK` ＋ 正確試結案後 `ROLLBACK` 復原

- **業務問題**：針對 `T029`（建立於 `'2024-03-25'`，目前狀態 `'處理中'`）做兩階段演練：

  2. **沙盒試算復原**：重開 `BEGIN;`，把 `T029` 試著結案在 `'2024-03-29'`（算出處理天數 `4` 天、總已結案件數變成 `21`），確認無誤後執行 **`ROLLBACK;`** 復原回 `20` 件已結案！
- **驗收條件**：誤填日期時被 `CHECK (closed_on >= created_on)` 攔下；第二段沙盒內已結案變 `21`，`ROLLBACK;` 後 `T029` 回復 `'處理中'`、已結案回復 **`20` 件**。
- **✍️ 在 DBeaver 動手作提示**：觸發 `CHECK` 報錯後必須先 `ROLLBACK;`，否則同一個交易區塊會被鎖死無法執行下一句 SQL！
