# 步驟 7～8｜用 Prompt 請 AI 開發與驗收桌面 App

這一階段由 AI 負責程式與環境設定，學生負責描述需求、操作測試、核對資料與回報問題。講義提供可直接使用的 Prompt，不要求學生手寫 Python。

先在 AI 開發工具中開啟你選的專案資料夾，準備好 `PRD.md`、`todolist.md`、`我的建表.sql`、`建立資料.sql` 與 `我的查詢.sql`。業務功能與測試數字以該專案的 PRD／待辦為準。

## 1. 先確認起始資料與需求

完成步驟 4 後，依 [共用操作指南](./學習與操作指南.md#做完-dml進入-app-前先還原) 還原本專案的初始資料，再貼上：

```text
請閱讀目前專案資料夾中的 PRD.md、todolist.md、我的建表.sql、建立資料.sql 與 我的查詢.sql。

我想透過你協助完成本機桌面 App，我負責實際操作與驗收，不手寫 Python。
請先用白話確認：
1. 這個工具給誰用，要解決什麼問題？
2. 每個功能對應哪個使用者故事？
3. 第一次啟動時應該看到哪些初始筆數與金額？
4. 哪些測試會修改資料，應該按什麼順序驗收？

請用 Microsoft Postgres MCP 唯讀確認實際資料庫與 schema、表結構及初始對帳數字。
如果資料狀態與驗收基準不同，先指出差異，提供讓我在 DBeaver 執行的還原步驟，
不要透過 MCP 修改資料，也不要為了符合現況而改掉驗收數字。
若缺少檔案或連線資訊，請列出真正缺少的項目，不要自行捏造。
這一步先確認需求與資料，不開始開發功能。
```

**學生要確認**：AI 說出的專案、資料庫、功能與初始數字都正確。門市專案此時使用第一季資料，還沒加入 4 月。

## 2. 請 AI 準備開發環境

> [!NOTE]
> **先分清楚兩件事**：前面步驟 1～6 使用的 `@microsoft/postgres-mcp` 透過 `npx` 直接執行，**不需要建立 Python 虛擬環境**；只有現在步驟 7 要在自己電腦上啟動 Python Tkinter 桌面視窗小工具（`app.py`），才需要依 `requirements.txt` 安裝 `psycopg2-binary` 與 `python-dotenv`。

```text
請協助我準備這個專案的桌面 App 開發環境。

請先檢查目前作業系統、專案資料夾、可用的 Python 與 Tkinter，
再依本專案的 requirements.txt 準備獨立環境及所需套件。
不要使用其他專案的套件清單，也不要改動其他專案的環境。

程式採用 Python + Tkinter + psycopg2 + python-dotenv。
請建立或檢查 .env，使用 DATABASE_URL 與 DB_SCHEMA 設定連線，
並把含密碼的設定與虛擬環境排除於 Git 追蹤之外。
App 需要新增／修改功能時，使用具備對應權限的練習帳號；MCP 仍維持唯讀。
若需要我填入連線資料，請給我清楚的填寫位置，讓我在本機輸入密碼。

請實際測試連線，只查詢目前資料庫、schema 與初始筆數，不修改資料。
完成後用白話告訴我：哪些準備已完成、測試結果是什麼、我下一步怎麼操作。
若有必須由我手動完成的安裝或設定，請依我的作業系統一步一步引導。
這一步先完成環境與連線，不開發全部業務功能。
```

**學生要確認**：連線目標和 DBeaver 相同、初始筆數一致；若無法連線，先解決再往下。

## 3. 請 AI 完成第一個可驗收功能

```text
請依 PRD.md 與 todolist.md，完成第一個未完成項目，一次只做這一項。
先讓我能啟動視窗，看到連線狀態及本專案的初始筆數。

請把需要的檔案直接建立在目前專案資料夾中。
入口使用 app.py，查詢放 queries.py；SQL 沿用我已驗證的 我的查詢.sql。
連線讀取 .env，並套用 DB_SCHEMA；使用者輸入要參數化，不拼接 SQL。
寫入成功要提交，失敗要還原並顯示清楚的中文訊息。
若操作影響 0 筆，要依需求說明原因，不能一律顯示成功。
不要透過 MCP 修改資料庫，實際業務寫入由我操作 App 測試。

完成後請：
1. 列出已建立或修改的檔案。
2. 依我的作業系統，告訴我從哪個資料夾、用什麼方式啟動。
3. 給我明確的操作步驟，以及應該看到的數字或訊息。
4. 說明你實際執行過哪些測試；沒有執行的不要說已通過。

先不要勾選待辦，等我親自操作並回覆「通過」才勾選。
```

**學生要確認**：視窗真的開得起來、連線與筆數正確。若工具不能直接存檔，請 AI 改成逐檔引導儲存，確認檔案存在後再啟動。

## 4. 後續每次只完成一項

```text
上一項我已親自驗收通過，請勾選那一項。
現在完成 todolist.md 的下一個未完成項目，一次只做這一項。

請沿用既有功能與已驗證的 SQL，不要重做整個專案。
完成後告訴我如何啟動、如何操作、應該看到什麼結果，
以及要用哪個 DBeaver 查詢或唯讀 MCP Prompt 核對資料。

查詢功能要核對筆數、排序與金額。
寫入功能要測正常操作，也要測待辦指定的錯誤案例，確認錯誤時資料不變。
測試依待辦順序進行，不要擅自清空資料。
若需要整套重測，先提供本專案的還原步驟，由我執行並完成對帳。

等我回覆「通過」，才勾選本項並繼續下一項。
```

**學生要確認**：每次只有一個新功能，且結果能和資料庫對上。不要只看 AI 回覆「完成」就勾選。

## 5. 結果不對時，用這段回報

```text
這一項沒有通過。

專案與待辦項目：（填入）
我做的操作：（填入）
應該看到：（貼上待辦的驗收條件）
實際看到：（描述畫面與資料庫結果）
完整錯誤訊息：（若有，貼上第一個錯誤及相關內容）

請先判斷是環境、連線、資料狀態、SQL 邏輯還是畫面更新問題，再修正。
不要修改驗收條件來配合錯誤結果，也不要透過 MCP 改資料。
修正後列出改動，提供同一個案例的重測方式，並確認先前通過的功能仍正常。
先不要把這個項目勾選為完成。
```

## 6. 全部完成後，請 AI 協助最後驗收

```text
請依 PRD.md 與 todolist.md 整理最後驗收清單。

請涵蓋啟動方式、初始資料、全部使用者故事、錯誤輸入、重複操作、
交易失敗還原，以及關閉後重新啟動。
每個案例都要寫清楚：起始狀態、我的操作、應該看到什麼、如何查庫核對。
請區分「你已實際測試」與「仍需我操作確認」，不要把尚未確認的項目標成通過。

請整理專案的使用說明，包含如何啟動、如何設定連線、如何還原練習資料。
程式中的真實密碼不可出現在文件中。
```

**完成標準**：學生能依 AI 提供的方式啟動 App，逐項操作並核對資料；所有待辦都經親自驗收，而不只是收到產生好的文件或程式。
