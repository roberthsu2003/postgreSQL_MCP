# 步驟 1｜讀懂 Excel 與故事：動手建表之前先想清楚

> 💻 Excel ｜ 🎯 學完你會：讀懂 user story，並決定每一欄要存什麼、能不能空白

## 🎬 情境

打開 [`耗材庫存表.xlsx`](./耗材庫存表.xlsx)，小林問你：「這張表搬進資料庫要怎麼規劃？」

先別急著寫 SQL。我們要先弄清楚兩件事：**小林要用這份資料做什麼**，以及**每一欄可以放什麼**。

## 1. 先看「需求」工作表

需求用一句固定的句型來寫，這就是 **user story（使用者故事）**：

> 身為 **誰**，我想要 **做什麼**，這樣才能 **得到什麼好處**。

| 編號 | 故事 | 驗收條件 |
|:---:|---|---|
| S1 | 身為總務，我想要看到庫存已經到安全水位的耗材以及要補多少，這樣才能在斷貨前補貨 | 現有庫存小於或等於安全庫存的品項全部列出，缺最多的排最前面 |
| S2 | 身為總務，我想要用品名關鍵字查到耗材放在哪裡，這樣才能在同事來問時馬上回答 | 輸入「碳粉」能列出所有碳粉匣的品名、庫存與存放位置 |
| S3 | 身為總務，我想要登記同事領用的數量並自動扣庫存，這樣才能不用再手動改 Excel 的數字 | 領用後庫存減少；領用量超過庫存時要被擋下，庫存不會變負數 |
| S4 | 身為總務，我想要登記新進的耗材，登錯時可以刪掉，這樣才能讓清單永遠和倉庫一致 | 品號重複時不能新增；刪除時只會刪到指定的那一筆 |
| S5 | 身為總務主管，我想要知道目前庫存的總金額，這樣才能在月底回報時不用另外試算 | 顯示一個總金額，等於每項單價乘以現有庫存的加總 |

**驗收條件**是用來判斷「做對了沒」的標準。寫得越具體，之後你要驗收 SQL 和 App 就越容易。

## 2. Excel 和資料庫的對照

| Excel | 資料庫 | 這一階段的例子 |
|---|---|---|
| 一個檔案 | 資料庫（database） | `supplies` |
| 工作表 | 資料表（table） | `supplies` |
| 標題列的一格 | 欄位（column） | `unit_price` |
| 一列資料 | 一筆資料（row） | 影印紙那一列 |
| 資料驗證 | 限制條件 | 庫存不能是負數 |

最大的差別是：Excel 什麼都讓你填，資料庫會**依照你訂的規則把錯誤資料擋下來**。

## 3. 決定每一欄的規格

看著「耗材庫存」工作表，逐欄問三個問題：

1. 這一欄放的是文字、整數還是日期？
2. 可以空白嗎？
3. 有沒有規則，例如不能重複、不能是負數、只能選哪幾種？

| Excel 標題 | 欄位名稱 | 型別 | 規則 | 為什麼 |
|---|---|---|---|---|
| 品號 | `item_code` | `VARCHAR(20)` | 必填、不能重複 | 每項耗材的身分證，也就是**主鍵** |
| 品名 | `name` | `VARCHAR(50)` | 必填 | 沒有品名就不知道是什麼 |
| 規格 | `spec` | `VARCHAR(50)` | 可空白 | 白板筆沒有規格 |
| 類別 | `category` | `VARCHAR(10)` | 必填，只能四種 | 紙張、碳粉墨水、文具、清潔用品 |
| 單位 | `unit` | `VARCHAR(5)` | 必填 | 箱、包、支 |
| 單價 | `unit_price` | `INT` | 必填，不能是負數 | 要拿來計算金額，必須是數字 |
| 現有庫存 | `current_stock` | `INT` | 必填，不能是負數，預設 0 | S3 要擋掉超領 |
| 安全庫存 | `safety_stock` | `INT` | 必填，不能是負數，預設 0 | S1 要拿來比較 |
| 存放位置 | `location` | `VARCHAR(30)` | 必填 | S2 要回答同事 |
| 最後盤點日 | `last_checked` | `DATE` | 可空白 | 新品項可能還沒盤點 |

> [!TIP]
> **品號為什麼是文字？** 因為它有英文和符號，也不會拿來加減。電話、統編也是同樣的道理：不用來計算的編號，就用文字存。

> [!NOTE]
> **庫存金額為什麼不開一欄？** 金額等於單價乘以庫存，查詢時再算就好。存成一欄的話，每次改庫存都要記得一起改，就會出現對不上的情況。

## ⚠️ 常見卡關

| 狀況 | 怎麼想 |
|---|---|
| 不確定能不能空白 | 問自己：「新增一筆資料時，這一欄有可能還不知道嗎？」 |
| 不確定用文字還是數字 | 問自己：「這一欄會拿來加總或比大小嗎？」 |
| 欄位名稱想用中文 | 建議用英文加底線，寫 SQL 和之後做 App 都比較不會出錯 |
