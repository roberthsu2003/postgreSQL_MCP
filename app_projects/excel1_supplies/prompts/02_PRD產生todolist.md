# 步驟 3：把 PRD.md 拆成 todolist.md，然後一項一項做

## 1. 複製以下提示詞給 AI

```markdown
請閱讀目前資料夾的 PRD.md，產生 todolist.md，用來開發 Python + Tkinter 的本機桌面 App。
我不是工程師，我會依照這份清單逐項驗收畫面。

拆解規則：
1. 依照使用者故事切分，一項對應一個我看得到的功能。不要按照「資料庫層、畫面層」來切分。
2. 第一項是「打開視窗，顯示已連線與耗材品項數」，確認連線成功。
3. 每一項做完，我都要能打開視窗實際操作。
4. 每一項都要包含：對應的故事編號、要做什麼、我要怎麼操作、應該看到什麼。
5. 「應該看到什麼」要寫出資料庫裡的真實資料或數字。
6. 最後一項是錯誤處理：輸入錯誤或連線失敗時，顯示中文訊息，程式不會當掉。

開發規則（之後實作時也要遵守）：
- SQL 請沿用 我的查詢.sql，放在 queries.py；視窗程式放在 app.py。
- 使用者輸入一律用 psycopg2 的 %s 參數傳遞，不可以用字串拼接 SQL。
- 連線資訊從 .env 的 DATABASE_URL 讀取，不可以寫在程式裡。
- App 使用 .env 的帳號連線，不要透過 MCP 寫入資料。

先產生 todolist.md 就好，不要開始寫程式。
```

## 2. 檢查 todolist

- [ ] 每一項都看得出對應哪則故事
- [ ] 每一項都寫了「應該看到什麼」
- [ ] 第一項是連線確認，最後一項是錯誤處理

可以和[範例 todolist](../todolist.md) 對照。

## 3. 一次做一項

每次都貼這段：

```markdown
請完成 todolist.md 的下一個未完成項目，只做這一項。
完成後告訴我要怎麼執行、怎麼操作，以及這一項用到的 SQL。
等我驗收通過並回覆「通過」，才把這一項打勾，再繼續下一項。
```

如果畫面和「應該看到什麼」不同，不要自己猜原因，把實際看到的內容告訴 AI：

```markdown
這一項沒有通過。我做了：（操作）。應該看到：（預期）。實際看到：（畫面或完整錯誤訊息）。
請先說明原因，再修改。
```

> [!TIP]
> 測試時資料被改亂了，在 DBeaver 執行 [`supplies_full.sql`](../supplies_full.sql) 就能恢復。這會把手動做過的修改一起還原。
