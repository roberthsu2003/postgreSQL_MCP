# PRD：差旅報銷審核小工具（範例成品）

> 這是範例。你請 AI 產生的內容會略有不同，只要涵蓋相同的故事和驗收條件即可。

## 1. 要解決的問題

會計和出納用 Excel 彙整報銷單，常常不知道該催誰審核、哪些單據該撥款，同一張發票也可能重複報帳。這個工具讓會計人員在自己的電腦上，掌握每張單據的狀態並完成審核。

**使用者**：一位會計或出納人員。審核動作由這位使用者依主管的決定代為登記。

## 2. 這次不做的事

- 不做帳號登入和簽核權限
- 不做網站或多人同時使用
- 不做部門預算控管
- 不做「已批准 → 待撥款 → 已撥款」的後續狀態變更
- 不上傳發票檔案

## 3. 功能

| 功能 | 故事 | 使用的 SQL（`我的查詢.sql`） |
|---|:---:|---|
| 待撥款清單與合計 | S1 | 查詢待撥款單據、加總金額 |
| 待審核清單 | S2 | 查詢待審核單據與主管 |
| 核准與駁回 | S3 | 只修改待審核的單據 |
| 新增費用類別 | S4 | 新增一個類別 |
| 新增報銷單 | S4 | 新增一張單據 |
| 部門已撥款總額 | S5 | 依部門加總已撥款金額 |

## 4. 驗收條件

以下數字以你在步驟 2 親手建立四張表並執行步驟 3「AI 產生資料交易檔（完成對帳後）」的 13 張初始報銷單（總金額 33,360）為準。若測試時把資料改亂，在 DBeaver 執行 `TRUNCATE TABLE claims, employees, categories, departments RESTART IDENTITY;` 後重新執行步驟 3 產生的交易檔即可恢復。

### 待撥款清單（S1）
- 我打開待撥款清單，應該看到 **2 張**單據，都是周美玲，合計 **5,180**。

### 待審核清單（S2）
- 我打開待審核清單，應該看到 **2 張**單據：黃雅婷的單由王經理審核，陳小華的單由張協理審核。

### 核准與駁回（S3）
- 我核准 `EXP20240313`，它應該從待審核清單消失，待審核剩下 1 張。
- 我再對這張單按駁回，應該看到「這張單已經審核過」，狀態仍然是已批准。

### 新增類別與報銷單（S4）
- 我新增「員工訓練」類別，它的編號應該是 10，並出現在類別選單中。
- 我用發票號碼 `GH-99887767` 新增一張 1,500 元的單，它應該出現在待審核清單。
- 我用同一個發票號碼再新增一次，應該看到「發票號碼已報銷過」，單據不會增加。
- 金額輸入 0，應該看到「金額必須大於 0」。

### 部門已撥款總額（S5）
- 我選擇業務部，應該看到已撥款總額 **3,430**。

## 5. 使用的資料

| 資料表 | 欄位 | 意思 | 用在 |
|---|---|---|---|
| `departments` | `dept_id`、`name` | 部門 | 清單、部門總額 |
| `departments` | `manager_name` | 主管 | 待審核清單 |
| `categories` | `category_id`、`name` | 費用類別 | 清單、新增 |
| `employees` | `emp_id`、`name`、`dept_id` | 員工與所屬部門 | 清單、新增報銷單 |
| `claims` | `claim_id`、`claim_date` | 單號與申請日期 | 全部功能 |
| `claims` | `emp_id`、`category_id` | 申請人與類別 | 全部功能 |
| `claims` | `description`、`invoice_no` | 說明與發票號碼 | 新增報銷單 |
| `claims` | `amount` | 金額 | 清單、合計 |
| `claims` | `status` | 狀態 | 清單、審核 |
