### 題目 1（S1）：製作單一課程的完整簽到表（合併內部與外部）

- **題目與驗收**：身為訓練承辦，輸入課程代碼 `C02`，一次列出所有報名學員（包含內部員工與外部來賓），並標示「身分（內部員工／外部來賓）」、「識別編號（工號或信箱）」、「姓名」、「部門或公司」與「出席狀態」。驗收應共 **7 筆**（內部 4 人＋外部 3 人），且兩位「陳小華」都要出現。
- **✍️ 在 DBeaver 動手作提示**：把兩張報名明細表各自 `JOIN` 對應的人員主表後，用 `UNION ALL` 上下接在一起（記得兩邊欄位數量、順序與型別要一致），再依 `身分`、`識別編號` 排序。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
SELECT
    '內部員工' AS 身分,
    e.emp_id AS 識別編號,
    e.name AS 姓名,
    e.dept AS 部門或公司,
    CASE ee.attended
        WHEN true THEN '出席'
        WHEN false THEN '缺席'
        ELSE '未登記'
    END AS 出席狀態
FROM employee_enrollments ee
JOIN employees e ON ee.emp_id = e.emp_id
WHERE ee.course_id = 'C02'

UNION ALL

SELECT
    '外部來賓' AS 身分,
    g.email AS 識別編號,
    g.name AS 姓名,
    g.company AS 部門或公司,
    CASE ge.attended
        WHEN true THEN '出席'
        WHEN false THEN '缺席'
        ELSE '未登記'
    END AS 出席狀態
FROM guest_enrollments ge
JOIN guests g ON ge.guest_id = g.guest_id
WHERE ge.course_id = 'C02'
ORDER BY 身分, 識別編號;
```

**寫法重點**：兩段查詢分別取出統一的文字標籤 `'內部員工'`／`'外部來賓'`，且將工號 `VARCHAR(10)` 與信箱 `VARCHAR(50)` 對齊在同一個位置；用 `UNION ALL` 合併後不主動去重、效能最好。

### 題目 2（S2）：統計不重複的總報名人數（避免同名誤合併）

- **題目與驗收**：身為訓練承辦，想知道這季總共服務過幾位「不重複的學員」（重複報多堂課只算 1 人，但**同名不同單位**要分開計算）。驗收結果應為 **11 人**。
- **✍️ 在 DBeaver 動手作提示**：在子查詢中取出 `(姓名, 部門或公司)` 並用 `UNION`（不加 `ALL`）自動去除同一人在不同課程的重複紀錄，最後外層包 `SELECT COUNT(*)`。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
SELECT COUNT(*) AS 報名總人數
FROM (
    SELECT e.name, e.dept AS 所屬單位
    FROM employee_enrollments ee
    JOIN employees e ON ee.emp_id = e.emp_id

    UNION

    SELECT g.name, g.company AS 所屬單位
    FROM guest_enrollments ge
    JOIN guests g ON ge.guest_id = g.guest_id
) AS unique_people;
```

**寫法重點**：如果子查詢只選 `name`，業務發展部的 `陳小華` 會和金福食品的 `陳小華` 被 `UNION` 誤合併成 10 人；加上 `所屬單位` 一起比對，才會正確保留為 **11 人**。

**實測輸出：**

|---:|
| 11 |

</details>

### 題目 4（S4）：每門課的內部實際出席人數（體驗 `LEFT JOIN` 條件位置差異）

- **題目與驗收**：身為人資主管，想查看每門課目前「實際出席 (`attended = true`)」的內部員工人數。驗收應顯示全部 **6 門課**：`C01` 為 3 人、`C02` 為 3 人、`C03` 為 2 人，而 `C04`、`C05`、`C06` 均保留在表上且顯示 **0**。
- **✍️ 在 DBeaver 動手作提示**：如果把 `attended = true` 寫進 `WHERE`，會把沒有人出席的 `C04`、`C05`、`C06` 整列濾掉！請把條件寫進 `LEFT JOIN ... ON c.course_id = ee.course_id AND ee.attended = true`。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
SELECT
    c.course_id,
    c.name AS 課程名稱,
    c.course_date AS 上課日期,
    COUNT(ee.emp_id) AS 內部出席人數
FROM courses c
LEFT JOIN employee_enrollments ee
    ON c.course_id = ee.course_id
   AND ee.attended = true
GROUP BY c.course_id, c.name, c.course_date
ORDER BY c.course_id;
```

**寫法重點**：寫在 `ON` 的 `AND ee.attended = true` 只決定右表哪些列要接過來；接不到任何出席紀錄的課程（`C04` 全員缺席、`C05` 無人報名、`C06` 尚未登記）因為左表 `courses` 仍被 `LEFT JOIN` 保留，所以會全部出現且計數為 `0`。

### 題目 5（S5）：安全登記尚未點名的出席狀態（防護型 `UPDATE`）

- **題目與驗收**：訓練承辦開始替 `C06` 登記出席：在 DBeaver 把 `C06` 的員工 `E01`（陳小華）登記為出席（`true`）；規定**只允許登記尚未登記（`attended IS NULL`）的紀錄**，因此第一次應更新 1 筆，緊接著誤按再登記為 `false` 時應該 `UPDATE 0`、原紀錄不會被覆蓋。
- **✍️ 在 DBeaver 動手作提示**：在 `UPDATE ... WHERE` 條件裡除了 `course_id = 'C06' AND emp_id = 'E01'`，一定要多加 `AND attended IS NULL`。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
-- 第一次登記：應該成功更新 1 筆（UPDATE 1）
UPDATE employee_enrollments
SET attended = true
WHERE course_id = 'C06'
  AND emp_id = 'E01'
  AND attended IS NULL;

-- 第二次重複嘗試改為未出席：因已非 NULL，應該更新 0 筆（UPDATE 0）
UPDATE employee_enrollments
SET attended = false
WHERE course_id = 'C06'
  AND emp_id = 'E01'
  AND attended IS NULL;

-- 驗收查詢 C06 目前的內部出席紀錄
SELECT course_id, emp_id, attended
FROM employee_enrollments
WHERE course_id = 'C06'
ORDER BY emp_id;
```

**寫法重點**：把「只能登記尚未點名紀錄」的業務規則直接放進 `WHERE attended IS NULL`，就從資料庫層杜絕誤觸覆蓋歷史出缺席紀錄的風險。注意判斷空值只能寫 `IS NULL`，不能寫 `= NULL`。

**實測輸出（執行兩次 `UPDATE` 後查詢）：**

| course_id | emp_id | attended |
|---|---|---|
| C06 | E01 | `true` |
| C06 | E04 | *NULL* |

</details>

- **✍️ 在 DBeaver 動手作提示**：用 `UNION ALL` 合併兩張明細表並各自 `JOIN courses` 取得課程名稱，篩選條件分別加上 `WHERE ee.attended = false` 與 `WHERE ge.attended = false`（不可誤抓 `IS NULL`）。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
SELECT
    ee.course_id,
    c.name AS 課程名稱,
    '內部員工' AS 身分,

FROM employee_enrollments ee
JOIN courses c ON ee.course_id = c.course_id
JOIN employees e ON ee.emp_id = e.emp_id
WHERE ee.attended = false

SELECT
    ge.course_id,
    c.name AS 課程名稱,
    '外部來賓' AS 身分,
    g.name AS 姓名,
    g.company AS 單位
FROM guest_enrollments ge
JOIN courses c ON ge.course_id = c.course_id
JOIN guests g ON ge.guest_id = g.guest_id
WHERE ge.attended = false
ORDER BY course_id, 身分, 姓名;
```

### 題目 7（E2）：挑出「內部出席人數仍為 0」的檢討課程清單

- **題目與驗收**：人資主管只想單獨抓出目前「內部出席人數 = 0」的課程追蹤原因。因為題目 5 已把 `C06 / E01` 登記出席，此時 `C06` 出席人數已變成 `1`，因此這份檢討清單只應該剩下 **`C04`** 與 **`C05`** 共 **2 門課**。
- **✍️ 在 DBeaver 動手作提示**：沿用題目 4 的 `LEFT JOIN ... ON c.course_id = ee.course_id AND ee.attended = true`，在 `GROUP BY` 之後加上 `HAVING COUNT(ee.emp_id) = 0`（不可以用 `WHERE` 過濾分組總數）。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
SELECT
    c.course_id,
    c.name AS 課程名稱,
    c.course_date AS 上課日期,
    COUNT(ee.emp_id) AS 內部出席人數
FROM courses c
LEFT JOIN employee_enrollments ee
    ON c.course_id = ee.course_id
   AND ee.attended = true
GROUP BY c.course_id, c.name, c.course_date
HAVING COUNT(ee.emp_id) = 0
ORDER BY c.course_id;
```

**寫法重點**：這題把 `ON`、`WHERE`、`HAVING` 三者分工展現得非常清楚：`ON` 負責過濾連接右表的有效出席紀錄、`GROUP BY` 分出全部 6 門課、`HAVING` 才拿分組計數後的結果篩出 `0` 人出席的課。

### 題目 8（E3）：全公司訓練總表（合併內外部報名與人數上限比例）

- **題目與驗收**：製作含內部與外部的整合課程統計表，列出每門課（含沒人報名的 `C05`）的 `人數上限`、`總報名人數`、`總出席人數` 與 `報名率百分比 (%)`。驗收共 **6 門課**，`C02` 報名率 **17.5%**、`C06` 總報名 **3** 人且總出席 **1** 人（15.0%）、`C05` 為 **0.0%**。
- **✍️ 在 DBeaver 動手作提示**：先用 CTE（`WITH all_enrollments AS (...)`）把內部與外部報名用 `UNION ALL` 統整成單純的 `(course_id, attended)` 兩欄，再從 `courses LEFT JOIN all_enrollments` 做彙總與百分比運算。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
WITH all_enrollments AS (
    SELECT course_id, attended FROM employee_enrollments
    UNION ALL
    SELECT course_id, attended FROM guest_enrollments
)
SELECT
    c.course_id,
    c.name AS 課程名稱,
    c.capacity AS 人數上限,
    COUNT(ae.course_id) AS 總報名人數,
    COUNT(*) FILTER (WHERE ae.attended = true) AS 總出席人數,
    ROUND(COUNT(ae.course_id) * 100.0 / c.capacity, 1) AS 報名率百分比
FROM courses c
LEFT JOIN all_enrollments ae ON c.course_id = ae.course_id
GROUP BY c.course_id, c.name, c.capacity
ORDER BY c.course_id;
```

**寫法重點**：用 `100.0`（帶小數點）相乘避免 PostgreSQL 整數除法把百分比無條件捨去成 `0`；使用 `COUNT(*) FILTER (WHERE ae.attended = true)` 可在同一個群組內優雅統計出席數而不影響 `總報名人數`。

**實測輸出（共 6 列）：**

| course_id | 課程名稱 | 人數上限 | 總報名人數 | 總出席人數 | 報名率百分比 |
|---|---|---:|---:|---:|---:|
| C01 | Excel 樞紐分析 | 30 | 6 | 4 | 20.0 |
| C02 | 資料安全入門 | 40 | 7 | 6 | 17.5 |
| C03 | 簡報表達技巧 | 20 | 3 | 3 | 15.0 |
| C04 | Power BI 入門 | 25 | 2 | 0 | 8.0 |
| C05 | AI 工具實務 | 50 | 0 | 0 | 0.0 |
| C06 | 跨部門溝通 | 20 | 3 | 1 | 15.0 |

</details>

### 題目 9（E4）：找出「曾報名卻從未實際出席過」的人員名單

- **題目與驗收**：人資部門想關心「有報名紀錄、但實際出席次數至今為 0」的員工與來賓。驗收應找出 **2 人**：內部員工 `劉國強`（報名 2 次、出席 0 次）與外部來賓 `孫佳蓉`（報名 2 次、出席 0 次）。
- **✍️ 在 DBeaver 動手作提示**：把員工報名統計與來賓報名統計各自用 `HAVING COUNT(*) FILTER (WHERE attended = true) = 0` 挑出後，用 `UNION ALL` 合併呈現。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
SELECT
    '內部員工' AS 身分,
    e.name AS 姓名,
    e.dept AS 單位,
    COUNT(ee.course_id) AS 報名次數,
    COUNT(*) FILTER (WHERE ee.attended = true) AS 出席次數
FROM employees e
JOIN employee_enrollments ee ON e.emp_id = ee.emp_id
GROUP BY e.emp_id, e.name, e.dept
HAVING COUNT(*) FILTER (WHERE ee.attended = true) = 0

UNION ALL

SELECT
    '外部來賓' AS 身分,
    g.name AS 姓名,
    g.company AS 單位,
    COUNT(ge.course_id) AS 報名次數,
    COUNT(*) FILTER (WHERE ge.attended = true) AS 出席次數
FROM guests g
JOIN guest_enrollments ge ON g.guest_id = ge.guest_id
GROUP BY g.guest_id, g.name, g.company
HAVING COUNT(*) FILTER (WHERE ge.attended = true) = 0
ORDER BY 身分, 姓名;
```

**寫法重點**：注意不能只找 `WHERE attended = false`，否則像 `孫佳蓉` 這樣有「1 次缺席 + 1 次未登記 (`NULL`)」的人若還曾經出席過別場也會被誤抓。透過 `GROUP BY` 人員再用 `HAVING COUNT(*) FILTER (WHERE attended = true) = 0`，才能真正精準找出「歷來總出席次數為 0」的學員。

**實測輸出（共 2 列）：**

| 身分 | 姓名 | 單位 | 報名次數 | 出席次數 |
|---|---|---|---|---:|
| 內部員工 | 劉國強 | 資訊技術部 | 2 | 0 |
| 外部來賓 | 孫佳蓉 | 大成科技 | 2 | 0 |

</details>

### 題目 10（E5）：Transaction 交易演練沙盒 — 批次課後點名與現場補報（後用 `ROLLBACK` 還原）

- **題目與驗收**：模擬 6/5 `C06 跨部門溝通` 課後整理名單：在同一個 `BEGIN ... ROLLBACK;` 交易沙盒內完成三件事——(1) 把 `C06` 其餘還沒登記的員工（`E04`）登記為出席 `true`；(2) 把 `C06` 的來賓 `孫佳蓉`（`guest_id = 2`）登記為缺席 `false`；(3) 現場補報名一位金福食品的來賓 `吳淑芬`（`guest_id = 5`）並直接記為出席 `true`。在交易內查驗 `C06` 完整 4 人名單後，執行 `ROLLBACK;` 讓資料維持原本狀態（`E04` 與來賓 `2` 仍為 `NULL`，來賓 `5` 尚未報名 `C06`）。
- **✍️ 在 DBeaver 動手作提示**：在 DBeaver 寫一段 `BEGIN; ... SELECT ...; ROLLBACK;` 並一次全部執行（或逐步執行確認前後差別），體會把跨表多筆操作綁成單一交易的威力。

<details>
<summary>參考解答與 PostgreSQL 實測結果</summary>

```sql
BEGIN;

-- 1. 補登 C06 尚未登記出席的內部員工（E04 張大同）為出席
UPDATE employee_enrollments
SET attended = true
WHERE course_id = 'C06' AND attended IS NULL;

-- 2. 補登 C06 來賓孫佳蓉 (guest_id = 2) 為缺席
UPDATE guest_enrollments
SET attended = false
WHERE course_id = 'C06' AND guest_id = 2 AND attended IS NULL;

-- 3. 現場補報來賓吳淑芬 (guest_id = 5) 並直接記為出席
INSERT INTO guest_enrollments (course_id, guest_id, attended)
VALUES ('C06', 5, true);

-- 4. 交易內立即驗收 C06 完整 4 人出席狀態
SELECT '內部員工' AS 身分, e.name AS 姓名, ee.attended AS 出席
FROM employee_enrollments ee JOIN employees e ON ee.emp_id = e.emp_id
WHERE ee.course_id = 'C06'
UNION ALL
SELECT '外部來賓' AS 身分, g.name AS 姓名, ge.attended AS 出席
FROM guest_enrollments ge JOIN guests g ON ge.guest_id = g.guest_id
WHERE ge.course_id = 'C06'
ORDER BY 身分, 姓名;

ROLLBACK;

-- 5. ROLLBACK 後確認一切恢復原狀（員工 E01 維持題目 5 的 true、E04 回到 NULL；來賓只剩 guest_id=2 且為 NULL）
SELECT course_id, emp_id, attended FROM employee_enrollments WHERE course_id = 'C06' ORDER BY emp_id;
SELECT course_id, guest_id, attended FROM guest_enrollments WHERE course_id = 'C06' ORDER BY guest_id;
```

**實測輸出 — 交易內 `ROLLBACK` 前查驗（共 4 列）：**

| 身分 | 姓名 | 出席 |
|---|---|---|
| 內部員工 | 張大同 | `true` |
| 內部員工 | 陳小華 | `true` |
| 外部來賓 | 吳淑芬 | `true` |
| 外部來賓 | 孫佳蓉 | `false` |

**實測輸出 — `ROLLBACK` 後確認已還原：**
- `employee_enrollments` (`C06`)：`E01 = true`、`E04 = NULL`（2 筆）
- `guest_enrollments` (`C06`)：`guest_id = 2, attended = NULL`（1 筆，無 `guest_id = 5`）

</details>

## ⚠️ 常見卡關

| 狀況 | 原因 | 怎麼解 |
|---|---|---|
| `UNION` 報錯欄位數量或型別不符 | 上下兩段 `SELECT` 的欄位順序沒對齊，或一邊文字一邊數字 | 確認對應位置的欄位數量一致、型別相容 |
| 沒人報名的 `C05` 變成 `1` 人 | 寫成 `COUNT(*)` 而不是 `COUNT(ee.emp_id)` | 統計右表出現次數時，欄位請放右表主鍵或非空外來鍵 |
| `C04`、`C05`、`C06` 在題目 4 整列消失 | 把 `ee.attended = true` 寫進 `WHERE` | 條件移進 `LEFT JOIN ... ON c.course_id = ee.course_id AND ee.attended = true` |
| 第二次登記出現「`UPDATE 1`」被覆蓋了 | 忘了加上 `AND attended IS NULL` | 把業務條件寫進 `WHERE`，不要依賴畫面按鈕防呆 |
