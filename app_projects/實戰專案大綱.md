## 畢業專題

做完專案後，學生可以用自己的 Excel 走一次同樣的流程：[畢業專題：換你的 Excel](./畢業專題_換你的Excel.md)。

## 每個專案的固定流程

```mermaid
flowchart LR
    A["Excel<br>與 user story"] --> B["手寫 DDL<br>蓋結構"]
    B --> C["AI 依結構<br>產生 INSERT 檔"]
    C --> D["匯入<br>與 Excel 對帳"]
    D --> E["手寫 DML<br>回答故事"]
    E --> F["AI 用唯讀 MCP<br>寫 PRD.md"]
    F --> G["todolist.md"]
    G --> H["個人桌面 App"]
```

| 工作 | 學生 | AI |
|---|:---:|:---:|
| 寫 story、驗收條件 | ✅ | 協助檢查 |
| 手寫 DDL、DML | ✅ | 只當助教 |
| 把 Excel 轉成 INSERT 交易檔 | 檢查與對帳 | ✅ |
| PRD.md、todolist.md | 審核與修改 | ✅ 用唯讀 MCP 讀結構 |
| Python 與視窗程式 | 依 todolist 驗收畫面 | ✅ |

每個專案都準備兩份檔案：

| 檔案 | 內容 | 用途 |
|---|---|---|
| `xxx_data.sql` | 只有 `BEGIN`、`INSERT`、`COMMIT` | 匯入學生手寫的表，同時檢查結構 |
| `xxx_full.sql` | `DROP`、`CREATE`、`INSERT` | 卡關時救援，或把資料恢復成初始狀態 |

專案 8 資料量大，`store_data.sql` 改用 `INSERT ... SELECT`，把 CSV 暫存表的資料放進正式表，AI 只看樣本寫語法。

判斷要不要拆表時，專案中只用四個問題：資料是否**重複**、**修改**時要改很多處、**刪除**一列會失去別的資料、**新增**時是否被迫缺資料。

## 轉換專案時要處理的事

- [ ] 現有 `.sql` 的 `DROP` 和 `IF NOT EXISTS` 寫法不一致（例如 `cafe_shop.sql`、`assets_inventory.sql` 用 `DROP`，`expense_tracker.sql` 用 `IF NOT EXISTS`），依雙檔模式整理。
