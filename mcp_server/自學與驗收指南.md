# 自學主線：用 Prompt 建立、測試與部署 MCP Server

你負責工具需求與實際驗收，AI 負責產生程式、準備環境及排除錯誤。不要求手寫 Python。各單元原有的程式碼與指令可作為選讀參考；第一次自學，先沿著本頁完成一個階段再往下。

保留原本的案例順序：單元 1 用門市練唯讀，單元 2 用圖書館練交易；單元 3 切換商店練遠端，單元 4 **沿用單元 3 同一份商店程式與資料**，只改部署位置。換案例時，要重新確認工具與資料庫，不能只改檔名。

## 英文不熟，先這樣讀

先開 [英文名詞與欄位對照](./英文名詞與欄位對照.md)。各單元的 README 及範例頁也有該案例欄位表。保留英文原名是為了正確輸入，中文用來理解：例如 `limit=3` 是最多回傳3筆，不是查編號3。

本頁所有 Prompt 都要求 AI 使用繁體中文，遇到英文原名要附中文用途。資料欄名、工具名稱與設定鍵保持英文，不因翻譯而修改。

## 課前準備：先請 AI 檢查

在 Antigravity 開啟整份教材的專案資料夾，貼上：

```text
請全程用繁體中文說明，英文欄位、工具與設定首次出現時附中文用途及一個例子，保留原名不改。
我要依 mcp_server/README.md 自學自訂 MCP Server，不手寫 Python。
請先閱讀本章導覽與我要做的單元，檢查：
1. 我的作業系統、目前專案根目錄、uv、Python 3.11 以上、Node.js 與 npx。
2. 使用本單元的 requirements.txt 準備獨立環境，使用 MCP 官方 Python SDK 2.x，
   不要混用另一個 fastmcp 套件或舊版 SDK 的 API。
3. DBeaver／資料庫是否能連線，本單元目標資料庫是否存在、需要的表是否完整。
4. Antigravity 實際讀取哪個 MCP 設定檔，如何查看連線狀態及重新載入。

請先回報「已通過、缺少、下一步」，有缺少項目就依我的作業系統逐步協助。
每個手動操作都說清楚在哪台電腦、哪個資料夾進行，以及完成後應看到什麼。
需要密碼時讓我在本機設定，不要把密碼寫入程式、講義或 Git。
MCP 檢查只做唯讀；需要匯入或還原資料時，提供 SQL 與操作位置讓我在 DBeaver 執行。

```

Inspector 需要 Node.js 的 `npx`；只安裝 uv 還不夠。安裝與 API 以 [官方 Python SDK 文件](https://py.sdk.modelcontextprotocol.io/) 為準。Antigravity 的設定位置與載入方式可對照 [官方 MCP 文件](https://antigravity.google/docs/mcp)。

## 資料庫與執行位置對照

**每份 SQL 各自匯入一個專用練習資料庫**。原始檔會刪除同名表再重建，不能把咖啡門市、商店等資料全塞進同一個 `practice`。已有同名正式資料庫時，請先另建練習環境。

| 單元／範例 | 目標資料庫 | 先匯入的資料 |
|---|---|---|
| 1 門市唯讀 | `mcp_cafe` | [cafe_shop.sql](../範例資料庫/中文範例資料庫/cafe_shop.sql) |
| 2 借還書 | `mcp_library` | [library.sql](../範例資料庫/中文範例資料庫/library.sql)，再執行 [借還書測試交易檔](./2_寫入型MCP_server/library_test_data.sql) |
| 3～4 商店遠端與部署 | `mcp_shop` | [shop.sql](../範例資料庫/中文範例資料庫/shop.sql) |
| 5 教務處 | `mcp_school` | [school.sql](../範例資料庫/中文範例資料庫/school.sql) |
| 5 股市 | `mcp_stock` | [stock_market.sql](../範例資料庫/中文範例資料庫/stock_market.sql) |
| 5 YouBike | 自備資料庫 | 未附資料，屬選讀，不列入必做驗收 |

下載 SQL：在 GitHub 檔案頁選 **Download raw file**，或開啟 **Raw** 另存成 UTF-8 `.sql`。建立資料庫後，切換 DBeaver 連線至目標庫，使用 **Execute SQL Script** 執行整份；失敗時先還原交易，排除第一個錯誤後再重跑。

| 目前在哪裡執行 MCP | 連資料庫的主機填什麼 | 誰要設定連線 |
|---|---|---|
| 個人電腦，DB 在樹莓派 | 樹莓派的區網 IP | 開發者設定 DATABASE_URI |
| 個人電腦，DB 也在同一電腦 | `localhost`，使用實際映射埠 | 開發者設定 DATABASE_URI |
| MCP 與 DB 在同一組 Compose 網路 | DB 服務名稱 `postgres`、埠 5432 | 伺服器端設定 DATABASE_URI |
| 員工連遠端 MCP | MCP 主機的 IP／網域、MCP 埠與 `/mcp` | 員工設定 MCP 網址及個人 Token，不填 DB 密碼 |

`localhost` 永遠代表「目前這個程式所在的電腦／容器」。`0.0.0.0` 是伺服器監聽設定，不是員工要填的連線網址。先在同一電腦測通，再測另一台電腦，最後才搬容器。

| 過關點 | 應看到什麼 |
|---|---|
| Inspector | 能列出且呼叫 3 個工具 |
| 正常查詢 | 與 DBeaver 相同條件的結果一致 |

| 參數錯誤 | 清楚拒絕，不執行任意 SQL |
| 專案掛載 | 從新對話能呼叫這 3 個自訂工具 |

全部通過再往下；生成程式但尚未連線成功，不算完成。
