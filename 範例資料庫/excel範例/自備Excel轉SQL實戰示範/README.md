# 實戰示範：上傳 Excel 檔 ➡️ 透過 AI 產生 SQL 交易檔完整教學

本目錄專門為學員提供一個**「端到端 (End-to-End)」的實體操作範例**。  
學生可以拿著這裡現成的 Excel 檔案，跟著教學步驟丟給 AI，親身體驗「日常上班 Excel 如何變成標準 PostgreSQL 交易檔」的全過程！

---

## 📁 範例目錄包含檔案

1. 📄 **[員工差旅與費用報銷單.xlsx](./員工差旅與費用報銷單.xlsx)**：
   * 職場最常見的「單一工作表」請款單（含報銷單號、申請日期、員工、部門、主管、費用類別、發票號碼、金額、審核狀態）。
2. 📄 **[expense_tracker.sql](./expense_tracker.sql)**：
   * **AI 根據這份 Excel 真正轉換產出的標準 SQL 交易檔實體**。
   * 包含 `BEGIN ... COMMIT` 交易區塊、3NF 正規化拆解為 4 張關聯表（部門、員工、類別、報銷單）、主外鍵約束與全部資料寫入語法。
3. 📖 **本教學手冊 (`README.md`)**：
   * 包含完整 Prompt 與對照驗證步驟。

---

## 🛠️ 三步驟手把手操作教學

### 步驟 1：下載並檢查 Excel 檔案
打開 [`員工差旅與費用報銷單.xlsx`](./員工差旅與費用報銷單.xlsx)，你會發現典型 Excel 的痛點：
* 陳小華申請了 4 筆費用，部門（業務部）與主管（張協理）就重複填寫了 4 次。
* 李副總身兼技術部與人事部主管，如果姓名打錯容易造成資料矛盾。
* 新進員工還沒報銷費用，在這張單一表裡就無法登記。

---

### 步驟 2：在對話框中附加 Excel 並發送 Prompt

> ⚠️ **教學規範提醒**：請明確要求 AI 輸出**純文字 SQL 交易碼**，不可以叫 MCP 寫入資料庫（讀取可以），確保每一條 SQL 都由你親自學習與審核！

開啟 Antigravity / Claude / ChatGPT 對話框，點擊「附加檔案（📎）」選取 **`員工差旅與費用報銷單.xlsx`**，然後貼上以下提示詞：

```markdown
你現在是一位資深 PostgreSQL 資料庫架構師與 SQL 教學助教。
我附上了一份公司日常使用的「員工差旅與費用報銷單.xlsx」資料範例。

【重要教學規範】：你可以用 MCP 讀取資料庫的結構和資料，但不可以透過 MCP 建立或修改資料庫。我需要學習手寫 SQL 語法，請直接在對話中為我產出標準完整的 SQL 程式碼區塊，供我複製至 DBeaver 手動執行。

請針對這份 Excel 執行以下任務：
1. 【問題診斷】：指出這份 Excel 單一工作表存在哪些資料重複與更新異常（3NF 痛點）。
2. 【關聯資料表設計（DDL）】：
   - 請將它拆解為符合第三正規化（3NF）的 PostgreSQL 資料表（例如：部門表、員工表、費用類別表、報銷單明細表）。
   - 包含主鍵 (PRIMARY KEY)、外來鍵 (FOREIGN KEY)、適當型別（VARCHAR, DATE, NUMERIC）與 CHECK 限制條件。
3. 【SQL 交易資料檔（DML）】：
   - 將 Excel 中的資料轉換為標準 SQL INSERT 語法。
   - 必須使用 BEGIN; 開頭，COMMIT; 結尾，且寫入順序必須遵守主從關聯（先主表後子表）。
4. 【手寫 SQL 查詢練功】：提供 2 個未來可以用在 Python 桌面 App 中的經典手寫查詢（例如：按部門統計報銷總額、查詢待主管審核的單據清單）。
```

---

### 步驟 3：對照 AI 產出的結果與執行建庫

發送後，AI 會在對話框中為你輸出完整的 SQL 交易程式碼。  
你可以將 AI 輸出的內容，與本目錄預先準備好的 **[`expense_tracker.sql`](./expense_tracker.sql)** 進行對照：

1. **檢查表結構（DDL）**：
   * 是否將部門抽離出 `expense_departments`？
   * 員工表 `expense_employees` 是否設有指向部門的外來鍵？
   * 報銷單表 `expense_claims` 的金額是否有 `CHECK (amount > 0)` 限制？
2. **在 DBeaver 中親自動手執行**：
   * 打開 DBeaver，連線至你的資料庫（本機 Docker 或 Supabase）。
   * 開啟 SQL 編輯器，貼上 SQL 交易檔內容。
   * 按下 `Alt + X` 執行整個檔案！
   * 重新整理左側資料表清單，看著 4 張關聯表順利建立，資料一筆不漏地匯入！

## 💻 終極目標：這份範例最後能做成什麼「個人桌面小 App」？

當你透過這套流程建立了 `expense_tracker` 資料庫後，就可以在自己電腦上用 **PyQt5** 打造一套**「企業費用報銷審批與預算追蹤桌面小視窗」**：

* **介面設計**：
  * 頂部下拉選單切換「業務部」、「技術部」、「行銷部」。
  * 中間表格 (`QTableWidget`) 列出該部門所有「待審核」的單據。
  * 右側按鈕：點擊「批准核銷」或「駁回」，背後觸發手寫 SQL：
    ```sql
    UPDATE expense_claims SET status = '已批准' WHERE claim_id = %s;
    ```
  * 底部狀態列手寫 SQL 統計：該部門本月累計報銷總金額。
